## 1. 対象ミッションと防衛機

- 敵補給施設を破壊する **M04 / M11 / M18 / M23 / M25 / M29** の左右各施設に「分散型防護装置」を適用する。味方補給施設の防衛ミッション（M01/M08/M15/M22/M28）には適用しない。
- 左右それぞれ、既存の初期配置敵小隊3機が専属防衛機。増援・中央小隊は含めない。敵の新規追加や初期配置変更はしない。
- 防衛機の撃破は恒久的に防護を弱め、増援や再出現で防護を回復させない。移動だけでは所属は変わらない。

| M | 左施設の防衛小隊ID | 右施設の防衛小隊ID | 中央（防衛機ではない） |
|---|---|---|---|
| M04 | `left-defenders` | `right-defenders` | `central-fire-support` |
| M11 | `west-depot-guards` | `east-depot-guards` | `central-tank` |
| M18 | `west-bunker` | `east-snipers` | `heavy-counterbattery` |
| M23 | `west-depot-guard` | `east-depot-fireline` | `armored-center` |
| M25 | `west-supply-shield` | `east-crossfire` | `heavy-flank-guard` |

実装前に難易度別のステージJSONとランタイムのユニットIDを照合し、同一個体の撃破を追跡する。

## 2. 防護倍率と計算順序【確定】

各施設の生存防衛機が3/2/1/0機の場合、**最終被ダメージ倍率は 1/2・2/3・5/6・1**（50% / 66⅔% / 83⅓% / 100%）。防護下限50%は正式採用値である。

**武器・攻撃・DEF・追加効果・固定ダメージ等から「防護適用前ダメージ」を確定し、最後に対象施設の防護倍率を一度だけ掛ける。** 整数化は切り捨て。有効な正のダメージは最低1を維持し、無効・非ダメージ攻撃は0のまま。施設の残HPで実減少量を上限処理するのはその後。

```text
preShieldDamage = 攻撃種別ごとの既存計算結果（燃焼などの固定値も含む）
shieldMultiplier = (6 - livingAssignedGuards) / 6  // 3→1/2, 2→2/3, 1→5/6, 0→1
if (attackIsLegal && preShieldDamage > 0)
  finalDamage = max(1, floor(preShieldDamage * shieldMultiplier))
else
  finalDamage = 0
actualHpLoss = min(facility.hp, finalDamage)
```

**適用対象に例外なし**：通常攻撃、連携攻撃、武装コンボ、武器・追加パーツ特殊攻撃、爆撃中心・周辺、衝突等の施設への追加ダメージ、燃焼の継続固定ダメージ、残留爆炎、その他あらゆる施設HP減少。固定ダメージを防護の前に計算する。防護倍率の二重適用は禁止。施設以外へのダメージにこの防護を適用しない。

## 3. 全攻撃行動からの施設ターゲティング【修正要】

敵補給施設を、合法な射程・射線・位置条件を満たす場合、敵機と同様に攻撃可能な**敵対オブジェクト**として扱う。施設は複数占有マスだが、HPは施設ごとに1つ。**同一攻撃／同一効果による同一施設への重複ヒットは禁止**。異なる攻撃や別個の継続効果はそれぞれ適用する。施設のマス単位の射程・射線・範囲判定と、対象ID単位のHP処理を分離する。

- **連携攻撃**：ライン連携、挟撃連携、デルタ連携を対象に追加。各連携の既存の隊形・射程・EN・1R1回制限・参加機条件を維持。ペア防御・防護陣など防御専用連携は施設攻撃に変更しない。
- **武装コンボ**：同系統と異系統の全採用組合せを対象に追加。二段攻撃、2対象、貫通、押し出し、拡散射撃の既存仕様を維持。施設は固定物なので押し出さない。斬撃＋射撃等の複数対象攻撃では各対象を個別に判定し、同じ施設を狙う際の重複・同一対象制限は既存コンボ仕様との整合をテストする。
- **爆撃／拡散射撃**：中心と周辺の双方で施設を候補に含める。複数マスが範囲内でも施設への同一効果ダメージは1回。既存の「空きマス着弾不可」「対象選択上限」「自動選択」などの正式仕様を維持。
- **武器・追加パーツ特殊攻撃**：全種類を一覧化し、直接攻撃・範囲・追撃・追加ダメージ・状態効果の各経路を監査する。既存の一部特殊攻撃には施設用パケットがあるが、全種類の網羅的成功は未確認。施設へのダメージ経路は最終的に共通防護処理へ統合する。

調査時の主な参照箇所：`battleWeaponActions.ts`（`hostileTargets`、`opposingUnits`、`commitRobotBattleWeaponCombo`、拡散射撃）、`formations.ts`、`commonCombat.ts`（デルタ）、`battleBatch.ts`、`battleFacilityActions.ts`、`specialFacilityTargets.ts`、`activeCombat.ts`、`remainingCombat.ts`、`battleBlast.ts`。**現在の連携攻撃・武装コンボは敵機対象処理を使用しており、施設を十分に扱えていない。**

## 4. 施設に適用する特殊効果【確定】

- **適用**：直接／追加／衝突／範囲ダメージ、燃焼・残留爆炎、防御力低下、マーキングによるダメージ増加など、施設に意味のある状態・ダメージ効果。
- **無効**：施設そのものの押し出し・引き寄せ・移動、移動力低下、行動不能・行動封鎖など、機体の移動／手番を前提とする効果。
- ダメージ部分と機体専用状態効果は分離する。特殊効果が施設に無効でも、合法な攻撃のダメージは無効化しない。防御低下・マーキング等の持続／解除タイミングは既存効果を尊重し、施設に手番がない場合の代替タイミングを明示してテストする。

## 5. 燃焼と残留爆炎【確定】

- **継続燃焼弾**：施設への初撃ダメージに加え、施設に燃焼状態を付与する。既存の燃焼固定値・継続回数・再付与時の非重複更新ルールを維持する。施設は自分のターンを持たないため、**ラウンド終了時に燃焼固定ダメージ**を発生させる。各tickの固定値を確定した後、施設防護倍率を最後に掛ける。
- **残留爆炎**：施設の占有マスが爆炎の範囲内にある場合、施設にも既存の固定ダメージを与える。施設1つにつき同一処理タイミングで重複しない。燃焼弾と残留爆炎は別ダメージ源として共存し、それぞれ防護を掛ける。施設への残留爆炎の適用タイミングはラウンド終了時とし、敵機の既存タイミングは変えない。
- 施設の燃焼・爆炎の残存状態、発生済みtick、ダメージ源の帰属、撃破・勝利判定、セーブ／ロードを正しく処理する。
- 調査時点：`activeCombat.ts` の継続燃焼弾は施設への初撃パケットがあるが `burns` はユニットIDのみ。`burning.ts` と `battleState.ts` のtickはユニット手番。`hazards.ts` の爆炎も敵ユニットを対象とし、施設は未対応。

## 6. UI【確定】

- **防衛機のマス色**：通常の敵機マス（赤）と区別。左施設の防衛機はアンバー／金色、右施設の防衛機は紫色。機体画像は残し、盾アイコン＋「左」「右」の表示を併用して色だけに依存しない。
- **敵機サマリー**：「補給施設 左 防衛機」「補給施設 右 防衛機」等を機体名と併記。非防衛機や増援には付けない。
- **施設サマリー**：「防衛機 2/3機」など生存数／初期数、対応する3機の名前・生存／撃破を一覧化。施設を選択すると対応する防衛機をマップで強調。
- **施設燃焼状態**：施設サマリーに「燃焼中」を表示する。
- **表示しない**：防護倍率・軽減率・防護ダメージ数値、および防衛機撃破時の「左補給施設の防護が弱まりました」等の通知。
- PC・スマートフォン横画面で、施設／防衛機の識別とタップ操作を確認する。

## 7. AI・勝利条件・セーブ互換性

- 友軍AIは防護が強いとき防衛機を優先。ただし施設への致死攻撃が可能、攻撃可能な防衛機がいない、または施設への有効ダメージが合理的に高い場合は施設を攻撃できる。既存AIの行動制限と戦術判断を壊さない。
- M04/M11/M18は施設破壊。**M23：施設破壊＋拠点2R確保、M25：施設破壊＋2機脱出、M29：施設破壊＋データ送信**。燃焼／残留爆炎／連携／コンボで施設HPが0になっても既存の複合条件を省略しない。
- 旧セーブを破壊・初期化しない。施設と初期防衛機の対応はステージ定義と保存済み戦闘状態から復元し、撃破済み防衛機を復活させない。旧セーブに存在しない施設燃焼は「燃焼なし」で補完。再ロード時に同じtickが二重発火しないことを確認する。
- 同一ゲームの機体・装備・パーツLv・報酬・ミッション進捗を維持する。

## 8. 実装と検証の受入条件

1. GitHub最新main・`AGENTS.md`・関連PRを再確認し、既存の施設攻撃APIとステージ定義を照合する。
2. 施設への全HP減少を捕捉する共通ダメージ精算を設計し、**防護倍率が最後に一度だけ適用される**Unit Test（通常・固定・連続・範囲・同一施設複数マス・最低1・0）を追加。
3. 全連携技、採用済み全武装コンボ、全武器／追加パーツ特殊攻撃の合法ターゲット・射程・状態異常・EN・撃破・重複防止を検証。敵機への従来挙動も維持。
4. 燃焼と残留爆炎の施設tick、同時存在、再付与、重複防止、破壊、撃破帰属、ラウンド境界、途中セーブ／再ロードを検証。
5. 全対象6ミッションのEasy/Normal/Hardで防衛機の対応・倍率推移・複合勝利条件を確認。必要に応じ短いsmoke／シミュレーション。
6. PC／スマホ横画面の防衛機色・盾・左右・施設サマリー・燃焼表示を確認。ゲーム固有型チェック、Unit、smoke、対象E2E、buildを変更リスクに応じ実施。
7. 既存セーブの後方互換性を最優先し、必要なデータ移行を設計。既存の無関係なゲームは変更しない。
