# ターン制タクティクス 第5段階：正式補給施設・残骸・輸送車（第2段階）

## 採用画像
ユーザー最終承認（2026-11-09）の3枚を正本とし、元の絵柄・俯瞰構図を維持した透過WebPを `src/client/games/robot-tactics/facility-v2/` に収録する。

- `depot-intact.webp` — 通常補給施設、208×144px、2マス占有（M04/M11）。
- `depot-destroyed.webp` — 完全破壊された残骸、208×144px、同一接地座標と表示サイズ。
- `convoy.webp` — 輸送車、152×152px、1マス占有（M05/M12）。

元画像はそれぞれ「高密度sf補給施設コンプレックス」「崩壊した未来工業施設モジュール」「六輪装甲カーゴトラック」。透明画素を保持し、接地位置の余白を統一する。**採用済み1方向のみ**使用し、未採用の車両回転画像を勝手に補完しない。

## 表示仕様
1. すべての画像は完全不透明（元画像内の透明背景を除く）。半透明になるのは従来どおり壁だけ（opacity .56）。
2. Stage 1の `robotFacilityPlacement` が占有セルの中心を足元として返す。補給施設2マスを1画像で描画し、HPを複製しない。
3. Coreから投影されるHPに従い、補給施設はHP>0で通常画像、HP=0で残骸画像へ切替。破壊後の「補」文字表示は取り除く。勝敗判定・移動阻害・射線は従来どおり。
4. 輸送車はCoreの `cells` を直接描画位置に使う。ラウンド末の経路移動がViewに反映され、保存・再読込後もその座標に表示される。モデル内のrouteIndexには手を加えない。
5. 画像は各1回だけSVG defsへ登録し、オブジェクトからuse参照する。ローカル単体HTMLに全て埋め込み、ネットワーク不要。
6. 壁・機体・施設の奥行き順はPR #135の `x+y` に従う。施設の画像をグリッドセルと別グループに置き、操作タップ領域は変えない。

## 検証
- 画像3種の透過・縮小・埋め込みデータURIの存在検査。
- 施設HP0の残骸への切替、2マス1画像、輸送車のM05/M12再読込・保存不変性。
- ターゲットゲームの型チェック、関連Vitest、PCとスマホ横画面のPlaywright、単独HTMLのビルド。
- 他ゲームの総合E2E・DB・通信テストは対象外。本番deploy、mainへのmergeは行わない。

注：画像転送が一時的に失敗した場合、この設計だけで第2段階完了としない。必ず3つのWebPがGitHub上に存在し、テストに通ることを確認する。
