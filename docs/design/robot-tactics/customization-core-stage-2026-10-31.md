# オフライン・カスタマイズ 第1段階

PR #81 `27793aa493d6529316567a22250532cf1e620a0d`に積み、PR #75のカスタマイズ仕様を段階実装する。仕様正本はPR #79 `8e1931929af0e80d8957395f1efcf6b485b6ebd8`に含まれる`customization-performance-ui-spec-2026-10-30.md`と既存成長／装備JSON。mainとAGENTS.mdを再確認し、数値は変更しない。

## 完成した範囲

- 操作機3コアの一覧から個別画面へ移動し、一覧へ戻る。フレーム、Lv、武器、CAPと共有EXPを確認できる。
- 個別画面に基本装備込みの7能力、6枠と追加パーツの現装備、コア育成の次Lv能力／CAP／必要EXPを表示する。追加パーツ補正の未接続は、装備時に明示する。
- コア／Lv／CAP／共有EXPの短い表示をスクロール中も固定。フレーム10種を縦一覧にし、選んだ行の直下に比較表と装備ボタンを展開する。別の行を選ぶと前の詳細を閉じる。
- 比較はフレーム自身の能力補正・移動タイプ。包括HPへコアHPを二重加算せず、Coreの成長を利用する。右列は符号付き数値と有利な緑／不利な赤。変化なしは「—」。機体全体の交換後数値を詳細へ重複掲載しない。
- M10の`frame-group: attack-2`報酬を、正本のグループに属するⅡ-A/B両モデルへ解決する。従来の進行層がグループIDを基本パーツへ登録していた不具合を修正し、旧version 1のM10リザルト表示領収も読み込めるよう保持する。
- フレーム交換は現在の解放状態とパーティ全体の装備制約を再検証する。同一グループの別モデル（攻撃型Ⅱ-A/Bを含む）も同時装備させない。未解放／他コアが使用するグループ／装備中を短く表示する。交換でEXPや基本パーツLvを変更しない。
- コア強化は1回につき1Lvのみ。正式40段階EXP表、共有EXP、Lv1〜41、CAP、成長補間、Lv21のMOV変化を利用する。画面から任意のEXPコストやLv、能力値は受け取らない。
- 進行編集は既存の保存トランザクションで1回確定し、保存成功後に画面へ公開する。期待revisionの不一致・同時操作・別画面の古い保存を拒否する。失敗時は元のLv／EXP／構成を維持して再試行できる。
- 戦闘中／未処理リザルト中の編集をSessionでも拒否。編集済み構成を出撃へ渡し、再挑戦も同じ出撃時構成を保持する。保存形式version 1と既存バックアップを維持する。

## 検証

- strict TypeScript（未使用、添字、optional検査を含む）。
- 新規Unit 14件：採用EXP合計10,135、全40段階、Lv21 MOV、最大Lv、EXP不足、フレーム制約、比較、旧形式の高Lvパーツ／M10リザルト維持、原子的保存、再送／同時／別画面、保存失敗、バックアップ、戦闘・リザルト中の禁止。
- PC1280×800／スマホ390×844の新規8件と既存オフライン8件。通信遮断した自己完結HTMLで、フレーム交換、比較色、解放／重複制約、共有EXP消費、IndexedDB失敗／再試行、再起動、編集後の出撃／再挑戦を確認する。
- 手動の画面確認でも固定表示・比較表・タップ領域・横はみ出しを確認。全ミッションの実戦／勝率試験ではない。EXP獲得からの接続は従来の保存契約fixtureの明示的な勝利入力を使用し、正規戦闘Coreが完成した意味にはしない。
- 専用CIは既存の対象Unit、4ビルド、戦闘／武器検査を維持し、既存offline構成に新規画面8件を追加する。

## 未実装の境界

基本パーツと追加パーツの交換、パーツ強化、性能チェックは後続。本工程で装備Lvの共有・保持単位やアップグレード移転を新ルールとして決めていない。過去の高Lv装備を読み込んだ場合も、そのLvを維持する。

拡散3組・衝撃3組は#81から未接続のまま。本工程の調査では、周辺対象の射線基準や、`pushCollisionRule: existing`が参照する押し出し方向／衝突停止の正式な共通処理を特定できなかった。現行の拒否を保持し、推測した空間ルールで6組を完成扱いにしない。仕様の追加検討や数値の再調整は行っていない。

本体の戦闘runtime未登録ガードは維持。共有サイト・他ゲーム・Workers/D1/WebSocket・配布方式を変更しない。本番deploy・migration・PRマージは行わない。中間PRは対象範囲の検証とし、Windowsとスマホ実機の導入／消灯／プロセス終了、最終配布方式は後続工程。
