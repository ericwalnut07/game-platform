# ターン制タクティクス：第5段階「斜め俯瞰マップ・地形画像」正式実装仕様

採用日：2026-11-08。開発正本：`ericwalnut07/game-platform`。独立・1人用・完全オフライン。PC／スマートフォン横画面。公開・統合・デプロイは行わない。

## 固定仕様（勝手に変えない）

- **A案**：内部の戦闘Core（正方グリッド、移動可能セル、LOS、敵AI、ダメージ、保存、勝敗、報酬、30面の配置）は変更せず、表示レイヤーだけ疑似アイソメトリック（2.5D）にする。新たな高低差・段差・障害物をルールに追加しない。
- **左下に味方、右上に敵**が向き合って見える斜め俯瞰の戦場構図を基本とする。既存の各ミッションの論理的な初期座標は変更しない。
- **全マスにSF金属床タイルを敷く**。通常床・警告ライン・整備床などの見た目を使い分けても移動補正やLOS効果を生じさせない。
- **味方機体の右斜め後ろ視点版を正式採用**。敵の正式画像は従来どおり。友軍AIも味方方向を基準にする。味方フレームの正式デザインと色違いを維持し、新しい視点画像がない場合は既存画像の無理な回転・反転で完成扱いにしない。
- **視認性優先**。壁・障害物は低め。HP・陣営色・選択・移動/攻撃範囲・施設目標が常に判別できるようにする。
- 機体・施設・障害物は**底面または足元がマスに接地**し、上方に少しだけはみ出す。奥側から手前側へ接地位置でソートし、重要UIは最前面表示。タップ判定は画像のはみ出しで隣接マスへ誤入力しない。
- 攻撃・連携・爆撃・通常/特殊移動・行動サマリー・演出速度・武器レイヤー・セーブ/再開はPR #122〜#125の成果を保護する。**移動は行動サマリーに表示しない**。

## 基準素材

2026-11-08に会話へ添付された2枚の素材シートを、第5-2・5-3の基準として扱う。

- 第1シート：床（金属パネル／警告ライン）、壁（直線・端部・L字）、コンテナ・バリケード・小型設備
- 第2シート：砲台、操作コンソール、通信塔、特殊施設・目標物、補給箱、レーダー設備

導入時は必要な透過素材を個別に切り出し、**既存の地形・施設データに対応する場合だけ配置**する。装飾品は通行・射線を遮らない。

## 工程（各段階ごとに独立して実装・検証）

### 第5-1：斜め俯瞰表示基盤（本PR）

- ひし形投影の可逆変換 `src/client/games/robot-tactics/BattleIsoProjection.ts` を表示専用に追加。
- 床・移動範囲・攻撃範囲・爆撃マーカー・移動ルート・地形を投影。機体・武器・HP/重要文字はビルボード補正で直立して表示。
- 投影されたカメラのviewBox／クリップ／フォーカス／俯瞰表示をPC・スマホの縦横比に合わせる。
- クリック・タップ／ドラッグ・ピンチ／キーボードを論理座標へ逆変換し、選択処理は既存のまま。
- 仮床・既存機体で構わない。**正式床画像・正式施設画像・味方新視点画像はまだ導入しない**。
- 投影Unit Test、PC／モバイルのマス選択・範囲・移動・保存・カメラ確認を行う。

### 第5-2：床・壁・障害物画像（実装済み・Draft #127）

- 第1素材シートを切り出し、すべての論理セルに床画像を敷く。
- 壁は既存の `board.walls` と一致させ、角・端・直線を正しく接続。箱・バリケード・小型設備も、既存のオブジェクトに限定して配置。
- 透過余白・接地位置・奥行き順と低い遮蔽物を調整。移動範囲/HPを隠さずタップ優先。


**第5-2実装記録（2026-11-08）**

- 2026-11-08添付の第1素材シート（7153.png、透明背景）から床2・壁3・コンテナ・バリケード・小設備の**8種類を切り出し**、80px×80px、4列×2行の透過WebPアトラス `terrain-v2/terrain-atlas.webp` として登録。元画像を勝手に描き直さない。画像SHA-256は `d8807a851ff7c1930034aa7864820497494afcccc1d7998dc3a4e8d9f2cee1dc`。ビルドで `?inline` としてHTML内に埋め込むため、通信なしの `file://` 実行を維持。
- `BattleTerrainArt.ts` が既存`board.walls`の4近傍接続を見て壁の横・縦・角を選択し、孤立している**元からある壁セルのみ**コンテナ／バリケード／小設備を表示。論理セルに壁・障害物は追加しない。床の警告パネルの出現は見た目だけで、移動・射線に影響なし。
- `BattleScreen.ts` の各論理セルに金属床を敷き、衝突壁を低い画像で表示。ひし形座標から接地位置`x+y`による奥行き順にソート。透過画像と範囲表示・HP・機体・文字・タップ判定を独立させる。アトラス画像1つを複数タイルで共有し、不要な巨大DOMを防ぐ。
- Core・武器・NPC・LOS・勝敗・セーブ互換に変更なし。施設は第5-3、味方新視点は第5-4に残す。
- Windows `ericwalnut` で型チェック・地形／投影Unit・独立HTMLビルド・新規PC/スマホ地形E2Eを対象検証。全ゲーム検証と本番操作は行わない。


### 第5-3：施設・目標物画像（実装済み・Draft PR #128）

- 第2素材シートから施設・通信塔・コンソールなどを取り出し、既存施設ID・占有セルへ接続。
- 施設の大型画像が隣接セルへはみ出しても、HP・データ送信等の操作を遮らない。

**第5-3実装記録（2026-11-08）**

- 第2採用素材シート `7154.png` の既存デザインを再描画せず、砲台・コンソール・通信塔・特殊目標ビーコン・補給箱・レーダーの**6個の透過素材**へ切り出した。96×96px、3列×2行の `facility-v1/facility-atlas.webp` にまとめて `?inline` 読込。SHA-256 `0902b45ee94876b7b208d7a530010fbc6651e0cb84725b84ce72955ce7841871`。外部通信が不要な独立HTMLを維持。
- `BattleFacilityArt.ts` と `BattleCoreView.ts` の表示専用対応：M01 `facility` → 防衛砲台、M04 `depot-left/depot-right` → 補給箱、M08 `facility` → レーダー、M11 `depot-west/depot-east` → 補給箱、M30 `allied-final-relay` → 通信塔。M05・M12の `convoy`（輸送車）と戦術デコイは、今回の第2シートに該当する正式画像がないため従来の識別表示を維持。
- Core側に既存の目標セルがあるM03・M10の7セル突破ラインは中央I2にビーコン1つ（各セルの目標表示は従来どおり）、M05・M12輸送先、M06・M13拠点、M07・M14データ取得／送信先には、対応する目標画像を表示。M30は既存のK3（データ取得）／I14（データ送信）を**表示用マーカーとしてのみ**投影し、ゲーム内オブジェクト・クリア条件・通行可能性・射線は変えない。M30の戦闘機能は現時点のアプリでは準備中のため、実画面で画像を確認したとは扱わない。
- 占有マスが2つの施設でも画像・HPバー・名称を**施設1件につき1つ**描画。画像は奥行き方向へ独立ソートし、HPと文字は上層、元のマス上のタップ判定と範囲表示は維持。施設画像のはみ出しは隣接マスの選択・データ操作を妨げない。
- Stage5-2の床/壁、正式ロボ本体/武器、VFX・セーブ・Coreを保護。新規Unit TestおよびPC・スマホ用の実ミッション表示・操作・リロードのE2Eを追加し、独立ロボ用CIに組み込む。第5-4・5-5は実装対象外。
