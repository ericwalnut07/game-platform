## 実装

- `BattleViewModel.ts`：Coreが確定した手番列、機体状態、完全な合法行動候補、射程外/射線遮断理由、確定後の被弾イベントを受ける型と選択処理。UIで距離・射線・SPD順・連携幾何を再計算しない。現在＋次の約3枠をそのまま表示し、小隊はCoreの共通1枠を維持する。
- `BattleScreen.ts` / `battle-screen.css`：約9×9フォーカスと俯瞰、俯瞰タップからフォーカス、ドラッグ/タッチパン、ピンチ/ボタン/ホイールズーム。表示操作はCore・ENを変更しない。画面比率による余白へ視界外マスを描画/選択しないようクリップする。
- 自機青・友軍緑・敵赤、簡易HP、現在機体/小隊の輪郭、下部固定の移動/攻撃/特殊/連携/待機。必要な候補だけを強調し、対象タップと最終「実行」を分離。薙ぎ払いはCoreから渡された敵の組合せを直接選択し、2体/3体の上限をUIで独自に緩和しない。
- 共用サマリー1領域。自機操作中の敵味方タップで名前・HP/EN・装備武器/Lvを表示し、確定行動で最新結果1件へ自動復帰。履歴・予想ダメージ・未来の敵行動を表示しない。通常移動の確定もサマリーへ反映する。
- `BattleAutoDriver.ts`：Coreが現在AIと判定した場合だけ約800ms後に共通AI選択処理を呼ぶ。敵には確認不要。友軍は初期自動、マニュアル指示時は5作戦の選択と対象/地点指定後に行動。自動/手動指示でAI判断関数を分けない。
- 指示承認はチェックポイント番号ではなくCoreの**手番ID**に紐付ける。同じ友軍手番の移動/設定保存で再承認を要求せず、次の手番では改めて確認する。実行待ちの同一チェックポイントを二度送らない。
- `aiInstructions.ts` と `offlineSession.configureAi`：AI設定だけの永続チェックポイント。実際の対象/盤面/命令合法性はruntimeが検証する。HP/EN/位置/手番/目標や最新行動結果を変更せず、既存の保存version 1を継承。行動・EN消費なしを別経路で表現する。
- `BattleEffects.ts`：6武器系統、連携/専用技の交換可能な仮SVG表示。確定した被弾セルへ実ダメージだけを表示。小隊の3ヒットは1つの確定バッチ後に3パルスで見せ、同じパルスの複数対象は同時表示。全体約800ms、非ダメージ技に数字を作らない。
- `BattleSessionBridge.ts`：保存済み状態の投影と、最新チェックポイント/合法候補の再照合を通じてUIとSessionを接続。保存成功後にだけHP/サマリー/エフェクトを更新する。指示・カメラ変更で古い攻撃演出を再生せず、直接復帰でも確定済み演出を再実行しない。
- `OfflineApp.ts`：同じ戦闘の更新で画面を作り直さず、カメラ・選択状態を保持するmount/update/pause/dispose契約を追加。既存fixtureの終了関数形式も互換維持。オプションと画面非表示でAIタイマーを停止し、閉じる/復帰で確定状態から進める。
- `OfflineStorage.ts`：同期的なIndexedDB書き込み失敗も捕捉してトランザクションを中止。未保存の被害を表示せず、再試行でも一度だけ反映する。
