# 共通シールド行動・シールド増幅器

起点：PR #86 `2ac8cc3bd09b6c58ec4132c905e6fec444dc2a45`。最新main・AGENTS.md・#79/#86のHEADを再確認。正本は`rules.json/combat/actions/shield`、`addons.json/shield-amplifier`、基本パーツの採用済み軽減表。数値・成長・EXP・CAP・武器・ボス・ミッション条件は変更しない。

## 共通Core

- `commitRobotBattleShield`は現在の操作機1機のシールドを1行動として確定する。通常はEN45・軽減45%、増幅器付きはEN60・軽減55%。必要ENを装備から計算し、外部のENコスト指定を使わない。通常移動後にも使用できるが、同じ手番に攻撃や別行動はできない。
- `getRobotShieldActionPlan`を実Coreと性能チェックで共有する。増幅器は基本シールドを45%→55%へ変更し、基本パーツ「シールド補助」は別の乗算軽減として維持する。Lv3ならダメージ係数は`0.45 × 0.875`。追加倍率は途中で丸めず共通の最終floor、合法なダメージ攻撃ごとの最低1保証へ渡す。
- 通常斬撃／薙ぎ払い・既存コンボの共通倍率処理へ有効なシールドを接続する。内部の解決済み攻撃バッチは軽減を再適用しない。ほかの攻撃解決器も、この共通倍率を使ってからバッチへ渡す構造とする。今回、全攻撃・反応・AIを完成させたものではない。
- 状態は次の自分の手番開始まで持続し、手番開始前に解除する。ラウンド切替だけでは解除しない。撃破時にも解除し、共通の再出撃で復活させない。回復・EN上限・通常命中回復の既存台帳を維持する。被弾のたびにシールドENを再消費しない。
- `addonEffects.ts`へ接続済み効果の検証をまとめ、EN3種の既存API形状を維持する。現在の接続対象はEN3種・移動2種・シールド増幅器。未知ID、重複、Lv、不正な移動選択、未対応効果を黙って無視しない。

## 保存と入力

戦闘Unitに任意の`shielded`を保存する。旧snapshotで未記録の場合は無効のまま読み、状態・EN・保存文字列を再計算しない。外側セーブversion 2、戦闘Core／runtime version 1、IndexedDB構造は変更しない。保存された有効状態は、生存・自分の行動終了・装備から求める消費ENとの整合も検証する。

状態・EN・行動終了を一括で保存し、保存成功後に表示する。保存失敗では元の状態を保ち、再試行・同じ要求の再送で再消費や敵行動の先行を起こさない。直接復帰は保存された有効状態を保ち、再挑戦は出撃時の構成から無効状態で開始する。シールド発動自体にダメージや攻撃エフェクトは発生しない。

`offline-formation-policy.json`に未確定と残るペア防御等との併用倍率を推測しない。現在のAPIでは未解決の状態効果との組合せを拒否する。これは部分実装の入力ガードで、正式な「併用禁止」の採用ではない。敵・友軍AIのシールド候補生成・実行接続も後続であり、操作機以外への新たな装備・行動制限をゲームルールとして採用しない。

## 画面と性能チェック

シールド中はマップの機体に水色の外枠を付け、機体サマリーの見出しに「シールド中」と表示する。最新行動サマリーは使用したENを示し、機体サマリーとの共用・次行動による上書きを維持する。固定5カテゴリーは増やさず、fixtureでは「特殊」からシールドを展開し、最終の実行操作で確定する。発動前に予想ダメージを表示しない。

採用UI仕様に合わせ、自機操作中は俯瞰の機体も1回タップでフォーカス移動と機体サマリー表示を行う。機体の選択・情報表示だけで行動やENを消費しない。空地点のタップによるフォーカス移動と、行動の最終実行操作を維持する。

性能チェックの「シールド中」は既に発動した状態の指定であり、現在ENが消費ENを下回っていても軽減を試算できる。発動EN45／60を別途表示し、発動可否の試算とは混同しない。増幅器を外す・シールド指定を解除すると共通計算へ戻る。実際の装備・共有Lv・EXP・進行・保存は変更しない。
