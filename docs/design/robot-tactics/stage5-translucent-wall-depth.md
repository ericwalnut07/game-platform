# ターン制タクティクス 第5段階：半透明壁と奥行き表示

## 背景と採用仕様
2026-11-09・PR #134試遊後のスマートフォン横画面 M02 にて、箱形の壁が背後の機体を完全に隠すことと、**奥の機体が前の壁より前面に表示される**問題を確認。以下の表示仕様を採用する。

1. 既存の箱形壁を半透明表示にし、壁の向こうにいる機体を輪郭・色・配置が確認できる程度に透けて表示する。壁の占有マスは引き続き判別できるよう、透明度を調整する。
2. 2.5D斜め俯瞰表示の**画面奥→手前**（論理座標の `x+y` が小さい→大きい）に沿い、機体と壁、施設を同じ描画順に並べる。手前の機体は後ろの壁を隠し、手前の壁は奥の機体を半透明に覆う。
3. 移動演出中も機体を常に最前面へ出さず、アニメーションで補間した位置の奥行きに合わせる。見た目以外の位置計算・ヒット判定は変更しない。
4. 既存の斜め投影、機体と武器の正式アート、足元位置、行動/対象マーカー、選択しやすさ、戦闘演出、セーブを維持する。

## 実装
- `BattleScreen.ts` の壁は、従来どおり既存のCoreのwall setに含まれるマス**だけ**で `robotTerrainWall` の既存の箱形画像を生成する。
- マスの `g[data-cell]` に `.robot-terrain-object-layer` を持たせ、その中に壁画像を配置。`protected-unit-layer.robot-depth-scene-layer` にすべてのセル・施設・移動中の機体を `x+y+1` 基準で奥行きソートして追加し、壁→全機体の固定重ね順を廃止。1マスにつき1つの描画・当たり判定のまま。
- CSS `.robot-terrain-object-layer {opacity:.56;pointer-events:none}` により既存の正式箱形WebPをアルファ合成し、**透明な見た目を実現**する。画像アトラス自体を複製/再生成しないため単体オフラインHTMLにもそのまま収録できる。床、機体、武器、HP、マーカーは通常の不透明度。
- 移動中は既存の `robotBattleMotionPosition` の補間座標で、画面奥行きバンドが変わった時に**移動中のSVG要素のみ**DOMの描画順を並べ替える。機体を再生成しないことで以前の色付き四角形フォールバックちらつきを防ぐ。
- マーカーや攻撃範囲は既存の論理マスSVGであるため動かさない。正面向き画像のbillboard transformも維持する。
- Coreルール、壁の移動阻害・射線遮断、NPC、装備、ミッション、得点、進捗、セーブv2、Cloudflare全般には一切変更を加えない。

## 検証観点
- PC/スマートフォン横画面の `I9` 壁：奥 `H8` 機体 ＜ 半透明壁 ＜ 手前 `I10` 機体のSVGドキュメント描画順を直接確認。
- 壁画像の計算済みopacity 0.56、マウス/タップ不干渉、カメラズーム、俯瞰、リロード、セーブの不変。
- テスト専用の移動形状付き機体で、移動中も壁より手前に無条件で出ず、既存の移動アニメーションが完走すること。
- 既存の正式M01アート、武器レイヤー、行動枠、選択操作、戦闘VFXの回帰。
- 作業はGitHub上の専用Draft PRに積み上げ、mainマージ・本番deploy・共通Webサイト統合は行わない。
