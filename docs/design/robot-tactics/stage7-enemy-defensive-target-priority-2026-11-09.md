# 戦闘改善 第3段階：防御系行動中の機体への敵AI攻撃優先度

## スコープ
- 親PR #145（第2段階の斜めライン連携）。第1・第2段階の変更は維持。
- 完全オフライン独立ゲーム。敵NPCの攻撃対象評価のみを変更。ダメージ、DEF、EN、勝敗、セーブ形式、UI、武器性能は変更しない。

## 有効な防御状態
- `defended === true`（防御）
- `shielded === true`（シールド）
- `formationDefense.some(kind === "protection")`（防護陣）
- ペア防御単独は対象外。複数の防御状態が重なっても基本ボーナスは1回のみ。状態の終了・解除は従来のCore寿命処理を利用し、終了後は優先度を付与しない。

## 敵NPCの攻撃評価
- 合法な通常攻撃候補に限り、対象の防御状態が有効なら基本 +220。
- 敵NPCの現在位置から生存中の味方側重要オブジェクト（輸送車、守るべき防衛施設）への線分上に防御機体がいる場合、さらに +520。
- 前面判定は輸送車の**現在**占有セルおよび複数マス施設の**全**占有セルを使用。射線や攻撃可否を変更しない。前面は敵とオブジェクトの間にあること（線分射影が厳密に0〜1）、横方向誤差0.75マス以内。
- 重要目標候補には +450。施設への通常攻撃の既存基本評価 +500、撃破可能性 +1000、実ダメージ、友軍の明示的集中攻撃 +10000は保持。敵NPCに限り、重要目標を無条件に先頭へ置く旧booleanソートを数値比較に統合する。友軍AIの優先順位は変更しない。
- これにより防御機体が優先されやすくなるが、射程・射線・撃破可能性・重要目標・実ダメージとの比較は残り、強制ターゲット固定やダメージ肩代わりは起きない。
- 移動候補の比較も敵NPCに限り重要目標のboolean先頭固定を外し、同じ攻撃評価スコアで比較する。既存ミッション別の移動位置優先条件は保持。

## 検証

- A=防御なし、B=防御ありかつ前面、C=防御あり非前面。M05/M12で **B > C > A** を確認。
- 正式敵AI通常攻撃は従来の `checkRobotAttackSpatial` / `getRobotBattleMemberNormalPacket` を使用。違法攻撃の候補追加なし。
- 対象Unit、型チェック、独立HTMLビルド、M05短時間smokeを実施。他ゲームのE2E・全ゲームverify・大量統計・本番デプロイは今回の変更対象外。
