# 戦闘Core 第1段階：基礎ダメージとEN

実装起点：装備Core PR #71 `893c6f2b821e121fabc213856d0ad63634457fc9`。
正本は `rules.json/combat` と、PR #72を取り込んだ `basic-parts.json`。
採用済みHP・成長・CAP・EXP・移動規則を変更しない。

## 基礎ダメージ

`src/games/robot-tactics/combatMath.ts` は次の採用式の算術部分を提供する。

`floor(10 * (attackStat + weaponPower) * actionMultiplier * areaMultiplier / targetDEF)`

- カタログから現在Lvの武器威力を解決。斬撃・打撃・刺突は近攻、
  アサルト・狙撃・爆撃は射攻を選ぶ。入力能力値は合成済みとし、
  コア／フレーム／装備を再加算しない。
- 通常1倍、薙ぎ払い0.7、爆撃中心0.7／隣接0.4、迎撃0.7の
  対象1機分の基礎値を求める。対象ごとにfloorし、先に合算しない。
- 0.7などの小数は十進分数として計算し、最後に一度だけ切り捨てる。
  浮動小数点の `10 * 9 * 0.7 / 3 = 20.999...` による誤差を防ぎ、
  この場合の数学的な答え21を保つ。新しいゲーム上の丸め規則ではない。
- DEFが正の小数でもそのまま計算し、勝手に整数化しない。
  DEF<=0は未採用の下限を補わず拒否する。

返す `baseDamage` は式の基礎値であり、最終被ダメージ・合法手ではない。
式の結果0は0のまま返し、未確定の最低ダメージを決めない。
射程／射線、対象数・配置・陣営、通常攻撃を選べる条件、
防御／シールド・追加パーツ、命中効果・反動・HP減算は後続層で扱う。
たとえば両刃の剣の反動丸めや超重レールガンの中間ENを、
この算術関数が採用済みとして解決することはない。

## EN台帳

`src/games/robot-tactics/energy.ts` は、生存機1機分の不変なリソース台帳。
HP・SPD・合法行動・イベント発生の正当性は後続のBattleStateが管理する。
外部入力から直接この台帳へイベントを流さない。

| 契機 | 採用値／制限 |
| --- | --- |
| 初期EN | `ceil(maxEN * 0.3)` |
| 通常移動成立 | +3、自分の手番に1回 |
| EN消費なしの通常攻撃命中 | `6 + floor(maxEN * 0.025)`、手番に1回 |
| 被ダメージ | +3、ラウンドに1回 |
| 自手番中の撃破 | +5、手番に1回 |
| 行動終了 | `4 + floor(maxEN * 0.025)`、手番に1回 |
| チャージ | `20 + floor(maxEN * 0.05)`、移動／行動終了回復と併用 |

各回復は最大ENで打ち止め。満タンで契機が発生した場合も回復枠を使う。
自手番開始は移動・命中・撃破の枠だけをリセットし、被弾枠を残す。
ラウンド開始は被弾枠をリセットする。

行動確定時にENを支払い、後の回復を先借りして不足ENの行動を認めない。
1手番1行動・終了1回を台帳でも検査する。総ENコストと行動種別は
後続の合法行動判定から渡す。EN消費攻撃と特殊行動は通常命中回復を得ない。
追加移動は行動のENを消費し、通常移動の+3を二重に得ない。
チャージによる次回攻撃バフを新設しない。

回復イベントは、生存・命中・撃破・実移動が確定してから通知する。
撃破機、同時攻撃の相互撃破、手番外の迎撃撃破・反応の詳細な順序は
この台帳だけでは解決しない。手番／ラウンドの進行と重複イベント管理は
BattleStateの責務であり、この台帳を完成済み戦闘ループとは扱わない。

通常の行動終了／チャージ回復後に、既存の
`applyRobotBasicEndTurnRecovery` で蓄電・回生・修復を一度だけ適用する。
`moved` と `usedExtraMove` は静止判定に引き渡す。

## 戦闘Core 第2段階：味方の撃破・再出撃

`alliedLifecycle.ts` は `current-group-combat.json/defeatAndRespawn` の
確定事項をPure TSの状態遷移として実装する。生存する自機3機と友軍AIを
受け取る投影であり、敵の再出撃や完成済みBattleStateではない。

- 同時撃破は1バッチとして処理。未知ID・重複ID・既に撃破済みのIDを
  含むリクエストは全体を拒否し、元Stateを変更しない。
- 自機の撃破IDをラウンドごとに保持し、異なる自機3機が同じラウンド内で
  撃破された時点で即敗北。友軍AIの撃破と前ラウンドの撃破は数えない。
  異なるラウンドの撃破で自機全機が再出撃待ちでも、それだけでは敗北しない。
- Rで撃破された機体はR+1を待機し、R+2開始時から帰還対象となる。
  敗北確定後のラウンド進行・再出撃は拒否する。
- 撃破バッチの時系列順、同時なら自機1→2→3・友軍AI1→2→3の順で、
  現在空いている優先出撃マスを1機ずつ確保する。配列の入力順には依存しない。
  壁・施設全マス・敵・生存味方・先に帰還した味方の占有を避ける。
- 空き枠がなければ翌ラウンドへ繰越し、元の撃破順を維持する。
  一部だけ帰還できる場合は、その機体だけを配置する。再出撃回数の制限は作らない。
- 帰還時は最大HP・最大ENの30%切上げ・状態異常解除・運搬物なし。
  フレーム／コアLv／装備／友軍指示などの追加設定は保持する。
  型でもHP・位置などの可変項目を広げ、初期の非null位置型を死後まで残さない。
- 運搬機の撃破時に、その場の座標と運搬物IDを落下イベントとして返す。
  ミッション側への配置、回収・帰還の勝利条件や操作コストは決めない。

再出撃枠は信頼済みのStage Catalogから渡す。出撃エリアの新設・並べ替えや
候補ステージの採用は行わない。戻った機体は後続の手番構築で通常通り扱う。
設定以外の行動済みフラグ・EN手番台帳・SPD手番表などはこの投影に含めず、
BattleState接続時に新しいラウンド／帰還に合わせて管理する。
致死ダメージの決定・同時攻撃の効果順・敵増援は後続層の責務とする。

- ダメージ／ENのUnit・装備接続smoke17件に、撃破／再出撃16件を追加。
- 既存の装備・育成・移動・Stage Catalogを含め、対象139テストPASS。
- M01〜M07の実カタログ出撃優先枠と、採用済み防御型I Lv11 HP98で
  撃破→待機→再出撃を短く照合。施設の未実装アダプタや敵戦闘を除くsmokeであり、
  ミッション全体の成功・難易度検証とは扱わない。
- 対象Core・対象テストのstrict TypeScript：PASS。
- 全90設定の正式起動ガードは維持。候補ステージを採用扱いにしない。
- 新規モジュールとテスト／本書だけを追加・更新し、既存Core・正本数値は変更しない。
- 未接続のPure TS変更のため、UI・build・E2E・migration・Windows総合検証は
  手元では省略。既存GitHub Actionsのチェック設定は維持する。
