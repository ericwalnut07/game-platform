# 戦闘Core 第1段階：基礎ダメージとEN

実装起点：装備Core PR #71 `893c6f2b821e121fabc213856d0ad63634457fc9`。
正本は `rules.json/combat` と、PR #72を取り込んだ `basic-parts.json`。
採用済みHP・成長・CAP・EXP・移動規則を変更しない。

## 基礎ダメージ

`src/games/robot-tactics/combatMath.ts` は次の採用式の算術部分を提供する。

`floor(10 * (attackStat + weaponPower) * actionMultiplier * areaMultiplier / targetDEF)`

- カタログから現在Lvの武器威力を解決。斬撃・打撃・刺突は近攻、
  アサルト・狙撃・爆撃は射攻を選ぶ。入力能力値は合成済みとし、
  コア／フレーム／装備を再加算しない。
- 通常1倍、薙ぎ払い0.7、爆撃中心0.7／隣接0.4、迎撃0.7の
  対象1機分の基礎値を求める。対象ごとにfloorし、先に合算しない。
- 0.7などの小数は十進分数として計算し、最後に一度だけ切り捨てる。
  浮動小数点の `10 * 9 * 0.7 / 3 = 20.999...` による誤差を防ぎ、
  この場合の数学的な答え21を保つ。新しいゲーム上の丸め規則ではない。
- DEFが正の小数でもそのまま計算し、勝手に整数化しない。
  DEF<=0は未採用の下限を補わず拒否する。

返す `baseDamage` は式の基礎値であり、最終被ダメージ・合法手ではない。
式の結果0は基礎値として保ち、後述の正式採用済み最低1保証を最終段階で適用する。
射程距離、対象数・配置・陣営、通常攻撃を選べる条件、
防御／シールド・追加パーツ、命中効果・反動・HP減算は後続層で扱う。
たとえば両刃の剣の反動丸めや超重レールガンの中間ENを、
この算術関数が採用済みとして解決することはない。

## EN台帳

`src/games/robot-tactics/energy.ts` は、生存機1機分の不変なリソース台帳。
HP・SPD・合法行動・イベント発生の正当性は後続のBattleStateが管理する。
外部入力から直接この台帳へイベントを流さない。

| 契機 | 採用値／制限 |
| --- | --- |
| 初期EN | `ceil(maxEN * 0.3)` |
| 通常移動成立 | +3、自分の手番に1回 |
| EN消費なしの通常攻撃命中 | `6 + floor(maxEN * 0.025)`、手番に1回 |
| 被ダメージ | +3、ラウンドに1回 |
| 自手番中の撃破 | +5、手番に1回 |
| 行動終了 | `4 + floor(maxEN * 0.025)`、手番に1回 |
| チャージ | `20 + floor(maxEN * 0.05)`、移動／行動終了回復と併用 |

各回復は最大ENで打ち止め。満タンで契機が発生した場合も回復枠を使う。
自手番開始は移動・命中・撃破の枠だけをリセットし、被弾枠を残す。
ラウンド開始は被弾枠をリセットする。

行動確定時にENを支払い、後の回復を先借りして不足ENの行動を認めない。
1手番1行動・終了1回を台帳でも検査する。総ENコストと行動種別は
後続の合法行動判定から渡す。EN消費攻撃と特殊行動は通常命中回復を得ない。
追加移動は行動のENを消費し、通常移動の+3を二重に得ない。
チャージによる次回攻撃バフを新設しない。

回復イベントは、生存・命中・撃破・実移動が確定してから通知する。
撃破機、同時攻撃の相互撃破、手番外の迎撃撃破・反応の詳細な順序は
この台帳だけでは解決しない。手番／ラウンドの進行と重複イベント管理は
BattleStateの責務であり、この台帳を完成済み戦闘ループとは扱わない。

通常の行動終了／チャージ回復後に、既存の
`applyRobotBasicEndTurnRecovery` で蓄電・回生・修復を一度だけ適用する。
`moved` と `usedExtraMove` は静止判定に引き渡す。

## 戦闘Core 第2段階：味方の撃破・再出撃

`alliedLifecycle.ts` は `current-group-combat.json/defeatAndRespawn` の
確定事項をPure TSの状態遷移として実装する。生存する自機3機と友軍AIを
受け取る投影であり、敵の再出撃や完成済みBattleStateではない。

- 同時撃破は1バッチとして処理。未知ID・重複ID・既に撃破済みのIDを
  含むリクエストは全体を拒否し、元Stateを変更しない。
- 自機の撃破IDをラウンドごとに保持し、異なる自機3機が同じラウンド内で
  撃破された時点で即敗北。友軍AIの撃破と前ラウンドの撃破は数えない。
  異なるラウンドの撃破で自機全機が再出撃待ちでも、それだけでは敗北しない。
- Rで撃破された機体はR+1を待機し、R+2開始時から帰還対象となる。
  敗北確定後のラウンド進行・再出撃は拒否する。
- 撃破バッチの時系列順、同時なら自機1→2→3・友軍AI1→2→3の順で、
  現在空いている優先出撃マスを1機ずつ確保する。配列の入力順には依存しない。
  壁・施設全マス・敵・生存味方・先に帰還した味方の占有を避ける。
- 空き枠がなければ翌ラウンドへ繰越し、元の撃破順を維持する。
  一部だけ帰還できる場合は、その機体だけを配置する。再出撃回数の制限は作らない。
- 帰還時は最大HP・最大ENの30%切上げ・状態異常解除・運搬物なし。
  フレーム／コアLv／装備／友軍指示などの追加設定は保持する。
  型でもHP・位置などの可変項目を広げ、初期の非null位置型を死後まで残さない。
- 運搬機の撃破時に、その場の座標と運搬物IDを落下イベントとして返す。
  ミッション側への配置、回収・帰還の勝利条件や操作コストは決めない。

再出撃枠は信頼済みのStage Catalogから渡す。出撃エリアの新設・並べ替えや
候補ステージの採用は行わない。戻った機体は後続の手番構築で通常通り扱う。
設定以外の行動済みフラグ・EN手番台帳・SPD手番表などはこの投影に含めず、
BattleState接続時に新しいラウンド／帰還に合わせて管理する。
致死ダメージの決定・同時攻撃の効果順・敵増援は後続層の責務とする。

## 戦闘Core 第3段階：友軍AIの固定装備・成長

`friendlyPresets.ts` で前衛援護・射撃支援・機動支援の3プリセットを解決する。
AI行動の選択ではなく、戦闘・再出撃で使用する能力値の準備段階。

- 各ミッション／難易度の敵基準コアLvを使用し、自機の実Lvでは拡大縮小しない。
  Lv1〜5/6〜10/11〜15/16〜20/21〜25/26〜30/31〜35/36〜41に対して
  基本装備6枠すべてをLv1/2/3/4/5/6/7/8とする採用済み対応を使用する。
- 固定フレーム・固定装備IDは採用カタログを参照し、能力値は現在の
  `frames.json` とPR #72統合済みの `basic-parts.json` から毎回合成する。
  自機と共有する合成ヘルパーを装備Coreから切り出し、HPの二重加算を避ける。
  友軍に架空の自機コアIDを割り当てたり、自機の同一フレーム制限を転用しない。
- 前衛援護の基準Lv21はHP155／近攻94／EN136、Lv41はHP233／近攻124／EN199。
  射撃支援Lv41はHP195／射攻134／EN247、機動支援Lv41はHP189／近攻134。
  `certifiedCheckpoints` の旧HP235／攻撃118等を実装の既定値にしない。
  同表の数値を履歴として残し、旧バランス参照であることをメタデータに記録した。
  以前の「中間Lvは試遊用仮補間」という説明も、10/30採用済み方式への参照に更新。
- 基準Lvが未確定のEasy等は能力値・装備Lv・初期ENも未解決とし、Lv1へ置換しない。
  中盤以降の候補ステージや正式起動ガードを、このアダプタが採用へ昇格させない。
- 自軍の実装備から友軍AI強化パーツを数え、+5/+10/+15%とMOV対象外を報告する。
  強化後の整数丸めは未確定なので、装備時の最終能力値・初期ENはnullと診断する。
  強化前の値を強化済みとして流用せず、新しい丸め方を自動採用しない。

この段階で確認待ちだった射線と最低ダメージは、次節の10/30正式指示で確定。
射程距離の方式とDEFが0以下になった場合の下限は引き続き未確定。

## 戦闘Core 第4段階：採用済み射線・最終最低ダメージ

数値調整PR #72とは独立した10/30の明示採用。正本は
`rules.json/combat/lineOfSight` と `finalDamage`。

`lineOfSight.ts` は攻撃側・対象のマス中心を結ぶ直線を追跡する。
壁内部を通る場合は遮断し、角をちょうど通る場合は両側の壁でのみ遮断。
片側だけの壁、味方・敵機体は遮断しない。通過／遮断の二択であり、
命中率・火力への補正はない。境界時刻を整数比で比較し、浮動小数点の
誤差や進行方向に依存した角判定を避ける。

施設は既定で透過。`blocksLineOfSight === true` を明示したものだけを
遮断物にできる。移動を妨げる属性からは推測しない。既存施設には新しい
遮断属性を付けず、M01施設の旧pending説明を採用済みの透過既定へ更新した。

`attackRange.ts` は射線と独立した射程ゲート。距離計算は信頼済みルール層の
依存関数として分離し、正式方式が未採用の現在はnullを渡して未解決を返す。
マンハッタン／Chebyshevのどちらも既定にしない。テストの距離関数・
in-range入力は射線／最終ダメージを検査するための内部fixtureであり、
正式距離方式の採用やクライアントへの上書き権限ではない。

`attackResolution.ts` の共通空間ゲートを通常攻撃・射程2近接・迎撃で共用。
デルタは既存の「通常射程・射線不要」を維持し、位置／参加者／EN等の
他の合法性まで免除しない。全般の合法性は後続BattleStateから受け取る。

`resolveRobotTargetDamage` は対象1体ずつ、合法性と射程／射線を先に確認する。
不成立・射程外・射線遮断・距離未解決・非ダメージ効果は0で終了し、
ダメージ計算自体を呼び出さない。合法なダメージ命中だけ、既存の基礎floor式と
すべての適用倍率／軽減を解決した後、`finalizeRobotDamage` で最低1にする。
範囲／連携でも各有効対象に適用し、基礎値を先に1へ引き上げない。

この変更は未知の軽減順や特殊効果の丸めを確定しない。最終値が1未満なら
採用済みの最低1を適用できるが、1以上の未丸め小数は新しい丸め方を選ばず拒否する。
DEF<=0も引き続き未採用のため拒否し、暫定DEF1を正式ルールへ混入させない。

PC／スマートフォンの将来UIには同じ理由コードと文言を利用できる。
`out-of-range` は「射程外です」、`line-of-sight-blocked` は
「壁により射線が遮られています」。明示的な遮断施設がある場合は別文言とする。
今回UIは未接続であり、試遊版PR #66の表示を更新したという意味ではない。

## 戦闘Core 第5段階：中量・重量敵の能力と2武器

`enemyPresets.ts` で採用済みの中量12モデル・重量9モデルを解決する。
正本は `medium-heavy-models.json` と
`current-group-combat.json/enemies/soloEnemies/{medium,heavy}/statGrowth`。

- 中量4系統・重量3系統のLv1/5/11/21/31/41表を使用。
  HP／近攻／射攻／DEF／SPD／ENは基準点間を線形補間・四捨五入。
  中量のMOVはLv21段階成長、重量の基礎MOVは全Lv固定を維持する。
- 敵の独立した採用済み基礎曲線を保持し、自機コアHPやフレーム曲線へ置換しない。
  PR #72由来の現行武器威力・武器補正は、現在の基本パーツカタログから解決する。
  A/B/Cの違いによるHP・攻撃力倍率や旧難易度倍率を加えない。
- 各モデルはカタログの異なる2武器を持ち、共通の基準コアLv帯から同じ武器Lv1〜8を選ぶ。
  共通Lv対応を `growth.ts` へ集約し、友軍側の旧exportは互換のため維持。
  軽量／中量・重量／友軍の3つの保存済みLv表も一致を検査する。
- 武器の明示MOV/SPD等の補正を一度ずつ加算。武器威力は攻撃ステータスへ加えず、
  基礎ダメージ式の武器項にだけ使用する。重量砲撃CのMOVは2−1−1を既存下限1へ収める。
  これは採用済み組合せの補正処理であり、新しい武器重複ルールではない。
- 敵の報酬武器使用は自機の所有・解放・CAP・コアIDと独立。
  現行採用の中量防御B Lv21はHP115／近攻88／DEF79／EN118、武器の制圧メイスLv5は威力74。
- ステージアダプタは初期配置の単独敵だけを対象に、保存済みモデル・敵基準Lvを渡す。
  M03〜M07はNormal=A／Hard=Bの正本を維持。Easyの未指定モデルをAで補完せず、
  ボスは専用Coreへ分離し、通常敵や試遊限定HP150/DEF55へ置き換えない。
  ステージ側の武器Lvが共通Lv帯と矛盾すれば拒否する。

`readyForStatUse` は能力値準備の完了だけを表す。移動タイプ・合法移動・
武器固有の未確定ENや反動・行動選択・AIスコア・特殊行動の実行は対象外。
射程距離やDEF下限、未確定丸めも決めない。軽量機の未確定装備は別実装のまま保つ。
全90設定の正式起動ガードと、候補ステージの未採用状態を引き続き維持する。
