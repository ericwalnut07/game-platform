# 追加パーツEN効果：第1段階

起点：PR #85 `1748d8db3930fcf780daf88121b2d70cbac2c8b8`。最新main・AGENTS.md・#79/#85を再確認し、既存の装備／共有Lv／保存の実装へ積み重ねる。正本は`addons.json`と`rules.json/combat/energy`。数値や採用条件は変更しない。

## 接続した効果

| 追加パーツ | 処理 |
| --- | --- |
| 開幕蓄電器 | 戦闘開始の`ceil(最大EN×30%)`に25を加え、最大ENで止める。 |
| 高速充電回路 | チャージの既存回復と行動終了回復に15を追加する。待機・通常攻撃等へは付与しない。 |
| 戦闘回収回路 | 合法な通常攻撃の命中回復1回に8を追加する。複数対象でも1手番1回。EN消費攻撃・コンボ・連携は既存の通常命中回復対象外を維持。 |

`addonEnergy.ts`はIDから正本の数値を読み、既存`energy.ts`へ委譲する。EN上限、行動確定前の回復禁止、命中回復済みフラグを独立に作り直さない。追加回復後も既存の基本パーツ回復を適用し、蓄電補助の静止条件や採用済みの回復順を維持する。死亡した発動機の行動終了回復は従来どおり行わない。

## 構成と保存

内部戦闘Unitへ任意の`addons`フィールドを追加し、信頼済みの出撃構成からID・必要な移動選択を保存する。従来のフィールド欠損は追加パーツなしとして読み、文字列やENを再計算・書換えしない。外側セーブversion 2、戦闘Core／runtime version 1、IndexedDB構造は維持する。

開幕補正はUnitの新規生成時だけ適用する。保存復号・直接復帰は保存ENをそのまま使い、共通の再出撃では従来の再出撃ENを使う。再挑戦は新しい戦闘IDで初期化するので、出撃時の同じ構成に開幕補正を1回だけ適用する。元の戦闘へ加算し続けない。

共通の攻撃確定処理は、命中回復を1回だけ解決し、HP・EN・撃破・手番と一緒にSessionで原子的に保存する。保存失敗時は公開状態・元の保存を保持し、再試行・同一要求再送で回復を二重適用しない。武器fixtureは保存addonsを出撃時の構成と照合し、欠損・差替えを拒否する。

未知ID・同一ID重複・Lv・不正な移動選択を拒否する。現在の戦闘Unitで接続を許可するのはEN3種と既存の移動設定2種まで。その他の効果は未接続として拒否し、効果を黙って無視して戦闘を進めない。ボスへ新たな追加パーツを付与せず、採用プリセットと異なるaddon付きボスも拒否する。これは部分実装の入力ガードであり、新しい装備禁止ルールではない。ホームでは従来どおり60種を解放・CAP条件で設定できる。

## 性能チェックと表示

EN3種と移動設定は攻撃・防御の数値補正を持たないため、その構成でも実戦と同じダメージCoreで試算を継続できる。性能チェックは最大EN／任意の現在ENを用いるダメージ試算のままで、手番回復のシミュレータではない。未対応パーツは名称を示して試算を止める。仮装備は実際の装備・共有Lv・EXP・進行・保存へ反映しない。能力表示が基本装備までであることも明示する。
