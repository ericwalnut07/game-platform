# 薙ぎ払いの合法対象・拡張装置

起点：PR #87 `7f49587b12d4a172c796ba55ca53da0250646af3`。最新main・AGENTS.md・#79/#87を再確認。幾何と操作の正本は#75の`battle-ui-spec-2026-10-30.md`、上限・威力・ENは`rules.json`／`basic-parts.json`／`addons.json`、コンボ例外は#79の採用資料。新しいバランスを採用する工程ではない。

## 共通の合法対象判定

`sweep.ts`は自機の上下左右に接する各3マス帯を作り、選んだ敵が同じ1本の帯にすべて入ることを判定する。方向ボタンや方向IDをクライアントへ要求せず、対象の組合せから判定する。反対側の敵同士など、個別には射程内でも同じ帯に入らない組合せを拒否する。単体の通常斬撃の幾何は変えない。

`getRobotBattleSweepOptions`は装備中の武器、現在の操作機、生存中の敵、既存のチェビシェフ射程・共通射線・上限・ENから候補の対象ID集合を列挙する。角の候補重複を除き、死体・味方・壁で射線が遮られた敵・射程外・EN不足の候補を出さない。最大8近隣機に対する組合せは4本の3マス帯内でだけ生成し、全盤面の部分集合探索はしない。

実行する`commitRobotBattleSlashAttack`も同じ装備上限と帯判定を使用する。外部の対象IDを信頼せず、重複・敵味方・生存・射程・射線・帯・ENを検証する。射程外と壁の不成立理由は従来の共通判定を優先し、単なる帯違いと区別する。候補表示は状態を変えず、最終実行だけで行動を確定する。

## 拡張装置と既存武器

- 薙ぎ払い拡張装置は既存のCAP20／Normal M18副目標報酬を維持し、対象上限+1、装備中の薙ぎ払いに追加EN15を適用する。少ない対象を選んだ場合も、装置を使う薙ぎ払いの追加ENは同じ。追加パーツにLvや新たなEXP費用は設けない。
- 通常武器の2体→3体、旋風の剣の数値上限3体→4体をそのまま計算する。装置は攻撃範囲を広げない。同じ3マス帯の判定を維持し、4マス目を生成しない。性能チェックの「合法な対象数」も帯内の1〜3体のまま。
- 1対象あたりの70%ダメージ、共通の最終floor・最低1保証、諸刃の剣の通常薙ぎ払い20%自傷を変更しない。自傷は各対象の実HP減少を合計した後に1回だけ切り捨て、発動機が撃破される場合も共通処理へ渡す。
- 追加ENは対象数によらず1行動に1回だけ消費。EN消費攻撃のため通常命中回復と戦闘回収回路+8は付与しない。既存の撃破・被弾・行動終了回復の回数と上限を維持する。
- 通常単体攻撃や全分類のコンボへ、薙ぎ払いの対象増加・追加EN15を重ねない。コンボ固有のEN・通常攻撃専用効果抑止を維持する。対象条件に合わない武器を持つ場合も、追加パーツの物理装備を禁止する新ルールは作らない。

## 保存・表示・性能チェック

全対象ダメージ・EN・自傷・撃破／再出撃待ち・行動終了を、既存のバッチとSessionで一括保存する。保存失敗では元の状態を保持し、再試行・再送で一部の対象だけ二重に攻撃しない。直接復帰でエフェクトを再実行せず、再挑戦は出撃時の構成と初期状態を復元する。セーブversion 2、Core／runtime version 1、IndexedDB構造を変更しない。

別ビルドの実武器Core fixtureへ`sweep`／`sweep-expanded`を追加する。Coreが返した対象集合をそのままタップ選択へ投影し、現在の選択に合う候補だけを強調する。選択中の上限とENは行動名に表示し、予想ダメージは表示しない。低ENのシールドを含め、実行不可のコマンドへ合法な実行choiceを付けないようfixtureの投影も修正した。無効な表示モデルを受け入れるために共通UI検証を緩めない。

性能チェックは同じ装備上限・EN15を使用する。合法な帯内配置を満たす前提の独立した同性能敵の試算で、任意配置を合法化する機能ではない。EN14では攻撃不成立として0ダメージ・自傷0。実装備・共有Lv・EXP・ミッション進行・保存を変更しない。残る未対応パーツは引き続き名称を示して停止する。
