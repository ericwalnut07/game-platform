## 今回の確定仕様

- お気に入りは各コア5件。名前・フレーム・武器2枠を含む基本装備6枠・追加パーツと移動タイプ設定を保存する。パーツLvは記録せず、適用時の共有Lvを使用。登録・呼出・別コアへのコピー・名前変更・上書き・削除を既存のrevision/CAS保存で確定する。
- 別コアへのコピー時、対象コアの必要CAPが上限を超えれば「CAP不足によりコピーできません」を表示し、一切適用しない。自コアへの呼出では通常の編集と同様、CAP超過を許可する。
- 別コア装着中の**同一フレーム**を選ぶとフレームだけを交換する。両コアのLv・武器・パーツはそれぞれ元のコアに残す。交換する両機について下限補正前のMOVが1未満なら拒否。CAP超過は交換を妨げない。別モデルの同グループ重複など、CAP以外の既存装備制限は維持する。
- 所有装備の変更・強化・保存と、出撃の判定を分離する。`canCustomize` / `customizationBlockingIssues` はCAP超過を除く編集・保存判定。従来の`canEquip` / `blockingIssues` は出撃用の厳格判定を維持し、性能チェックや正式戦闘の出撃境界も引き続きCAPを検証する。
- どれか1コアがCAP超過なら「合計CAPオーバーのため出撃できません」。ミッション選択への遷移を止め、UIを迂回した`session.start`でも拒否する。修復後は選択・出撃を許可。武器・基本パーツ強化は共有EXPで実行し、全装備コアへ共有Lvを反映する。
- 実カスタマイズ一覧は獲得済み武器・基本/追加パーツと解放済みフレームだけ表示。別機能の性能チェックは従来どおり未獲得装備の試算を維持。
- 戦闘コマンドは装備の系統・レアリティ・追加パーツ・チームの連携拡張の有無で表示する。EN不足、射程/射線、配置、移動前、ラウンド内使用済み等はCoreの判定理由を表示し、技自体は残して実行を禁止する。射程1近接武器の特攻は「攻撃」へ配置。武装コンボは全6分類を「武装コンボ：技名（EN○○）」へ統一し、既存の採用技名を使用する（同系統は「同系統強化コンボ」）。効果・対象操作・ENは変更しない。
- 通常追加移動は3マス/EN30。ブースト補助は4マス、Lv1/5/8/10でEN30/25/20/15。Lv1〜10は既存の線形補間・整数丸めで30/29/28/26/25/23/22/20/18/15。他性能・使用条件は不変。

## 保存互換性と境界

保存format/versionは従来のv2を維持し、`progress.favorites` は省略可能な追加フィールド。既存v1は従来の共有Lv移行を使用する。お気に入りの名前、個数、コアID、所有ID、部位、武器重複、追加パーツの設定等を読み込み時に検証する。戦闘途中・リザルト待機中の編集禁止、保存失敗前の状態を公開しない処理、二重/古い入力の拒否、バックアップ経路を継承する。CAP超過の進行データは保存/復元できるが、CAP超過の戦闘出撃データは拒否する。

M01/M02等の未確定副目標、追加パーツ3件の一部接続範囲、M08以降の正式戦闘未接続は維持。既存武器/追加パーツのCAP・獲得・強化EXP、ミッション/AI/報酬は今回の変更対象外。上記EN値は旧`equipment-growth-rebalance-2026-10-30.md`、`common-combat-status-2026-11-03.md`の履歴値を置き換える。
