# ロボット戦術：カスタマイズ・育成・性能チェックの確定UI仕様

確定日：2026-10-30／対象：個人用・完全オフライン版。ゲーム数値・装備制約は既存正式JSON／Coreの値を参照し、この文書で変更しない。

## 1. パーティ全体一覧と個別コア画面

### パーティ全体一覧

- 直接操作する**3コアを縦に一覧表示**。各コアは機体／フレーム、Lv、現在の主な装備、使用CAP／上限CAPを短く確認できる。
- 一覧のコア1つをタップすると**そのコアの個別カスタマイズ画面**へ移動。戻る操作で同じ全体一覧へ戻る。
- 一覧は編成比較のための画面で、全パーツ編集を1画面に詰め込まない。

### コア個別カスタマイズ

- 上部にコア名・Lv・共有EXP、**現在の機体全ステータスと使用CAP／上限CAP**を確認できる領域を設ける。
- 装備カテゴリーの切替で、**フレーム、武器①、武器②、装甲、エンジン、制御、特殊、追加パーツ**を選択できる。基本装備はエンジン1／武器2／装甲1／制御1／特殊1の6枠。
- 選択カテゴリーに所属するパーツを**縦一覧**。入りきらない部分はスクロールして表示。選択中のカテゴリーとコア・CAPが把握できるようにする。
- パーツの行をタップすると、**その行の直下に詳細表と「装備する」ボタンを展開**。別パーツ行をタップすると前の詳細は閉じる。装備中・未解放・CAP超過等は簡潔に示す。
- 装備を確定したら上部のステータス／CAPへ**即時反映**。機体全体の装備後ステータスをパーツ詳細に重複表示しない。
- スマホでは画面遷移を浅くし、パーツ一覧だけは必要なだけ縦スクロール可能とする。無理に全パーツを1画面へ押し込まない。

## 2. パーツ詳細表：1つの表で「パーツ性能＋差分」

パーツ詳細を縦に並べ、**左：項目／中央：選択したパーツ自体の性能／右：現在装備中のものから交換した場合の変化**とする。

武器の例（**以下の数値はレイアウト説明用の仮値**）：

| 項目 | 選択パーツの性能 | 現在装備との差 |
| --- | ---: | ---: |
| 武器系統 | 斬撃 | — |
| 武器威力 | 42 | +12 |
| 近接攻撃 | +18 | +8 |
| 射程 | 1 | — |
| 必要CAP | 24 | +6 |
| 特殊効果 | 薙ぎ払い | 追加 |

- 右列は括弧を付けず、**符号＋数値のみ（+12／-8等）**。変化なしは「—」。
- **有利な変化を緑、不利な変化を赤**にする。必要CAPが増える場合は**赤（負担増）**、CAPが減る場合は緑。単なる符号ではなくその項目の意味で色を決定する。
- 武器威力と近接／射撃攻撃の**装備補正**を別項目として表示する。射程、特殊効果、移動タイプ変更など定性的な項目は短い名称や「追加／消失」「直線→全方向」のように簡潔にする。
- フレームは能力補正・移動タイプ、装甲・エンジン等は固有の性能と変化、追加パーツは効果と必要CAP等、そのカテゴリーに実在する項目だけ表示する。
- **装備後の機体全体の最終数値はこの表に載せない**。上部のコアステータスで確認する。
- 個別装備の交換は、選択した部位の旧装備と新装備の比較として計算する。追加パーツは追加／解除による差分として扱う。
- 「装備する」の下に無駄な情報や長い説明文を増やさない。

### 装備制限は従来どおり

- 同じコアの武器①②に**同一武器IDの二重装備は禁止**。異なるコア間の同一武器IDは許可。
- 同一フレームグループの3コア内重複は禁止。フレームは既存の合法候補から変更可能。
- 追加パーツは固定1枠ではなく、**CAP制限内で複数装備可能**。同じ追加パーツIDを1コア内に重ねない既存制約も維持。
- 未解放・CAP不足・枠違反は装備を確定せず、理由を表示。ルールやCAPの緩和はしない。

## 3. コア育成とパーツ強化

別の育成専用画面は追加せず、**コア個別カスタマイズに統合**する。

- **コア育成**：個別画面上部で現在Lv→次Lv、上がる能力値、CAP増加、必要EXPを確認して強化。
- **パーツ強化**：各パーツの展開詳細に「装備する」と合わせて「強化する」を配置し、次Lvの性能・CAP変化・必要EXPを表示して強化。
- **共有EXP残高**を画面上部で常時表示。強化実行で残高と該当レベルの表示が更新される。
- 既存の**コアLv1〜41・基本パーツLv1〜10**を使用。Lvのない追加パーツにはレベルアップボタンを出さない。
- EXP不足、最大Lv、CAP等の制約で強化できない場合は短い理由を表示し、無効操作にする。
- 強化に伴う実際のEXP消費・補正値・端数・制約は rules.json と該当パーツ正本を使い、仮の例示値で実装しない。
- **出撃中はカスタマイズ・強化不可**。中断状態から戦闘画面へ直接戻るため、戦闘途中でこれらの画面へ遷移できない。

## 4. 性能チェック（新規モード）

ホーム画面の独立メニュー**「性能チェック」**から入る。ゲームルール画面を複雑にする代わりに、実戦に出撃せず装備構成と敵の強さを試せる機能。

- **実際のセーブデータを変更しない**独立した試算環境。初期値は現在の自軍コア構成を読み込める。
- 自軍側は3コアの選択、コアLv、フレーム、武器・各基本装備、追加パーツとそのLv／効果を仮変更可能。
- 敵側はHP、近攻、射攻、防御、EN、武器威力などを自由に編集可能。仮想敵として扱う。
- 攻撃条件として武器・通常攻撃／強化攻撃／連携・特殊攻撃、対応する防御条件を指定し、**与ダメージ／被ダメージ**を計算して大きく表示する。
- 計算は**実戦のCore戦闘計算を共有**し、性能チェック専用の近似式で実戦値と食い違わせない。参加機体、EN、範囲、各技の条件等は既存計算仕様に従う。
- ルール外の仮装備（CAP超過など）も数値比較のため試せるものとし、**実戦では使用不能**と表示する。試算可能であることは実ゲームでの合法性を意味しない。
- EXP、実装備、コア／パーツレベル、クリア進行、保存中の戦闘は一切書き換えない。
- **戦闘中は性能チェックへアクセスできない**。

性能チェック用の敵／攻撃条件UIは小さな入力と切替式にし、詳細式や過剰な装飾を常時表示しない。

## 5. ゲームルール表示

このゲームは個人専用。短い「ゲームの流れ」「移動・攻撃・特殊・連携の操作」「勝利目標の確認」程度の説明で十分。詳細戦闘数式の百科事典や長いチュートリアルは必須ではない。実装のルール正本自体は別資料で管理する。

## 実装境界

本書はUI・機能仕様の**採用を記録する文書**であり、完成画面・計算器が動作したという意味ではない。具体的なパーツ性能・ダメージは rules.json、basic-parts.json、frames.json、addons.json と対応するTypeScript Coreを使用する。UI説明用ダミー数値を本番値として転記しない。
