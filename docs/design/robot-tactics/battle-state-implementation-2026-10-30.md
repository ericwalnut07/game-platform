# 第3段階：戦闘状態・同時攻撃・目標・保存の接続

PR #77の戦闘表示に続き、既存の共通Coreを一つの戦闘状態へ接続する。数値・ゲームルールの追加採用ではない。PR #72の育成値、6ボスの確定値、PR #75の4仕様書は変更しない。

## 接続した範囲

- `src/games/robot-tactics/battleState.ts`：HP・EN・配置・装備・行動枠・AI指示・目標を持つ版付き状態。ボス／味方の補助台帳にHP/ENを二重保持しない。通常移動、待機／チャージ、ボス号令、M30取得／送信、手番終了、ラウンド境界を既存関数へ接続する。
- `battleBatch.ts`：信頼済み上位resolverが共通ダメージ計算・合法性・効果処理を完了した**自手番の対敵同時攻撃**を確定する。同じ事前状態から全命中を集計し、EN消費・回復、HP、ボス支援解除、味方撃破／データ落下、勝敗、行動領収を一括更新する。攻撃途中で目標が破壊されても後続の同時命中を省略しない。
- `m30Mission.ts`：施設への同時攻撃バッチ。1攻撃がJ13/K13両方に当たっても共有HPへの適用は1回。小隊3機が別々に攻撃した場合は3回分を合計し、全攻撃IDを記録する。重複バッチを再適用しない。
- 味方のR+2再出撃は既存の優先順・合法配置・満HP／切上げ30%EN・状態解除を使用し、敵やボスを再出撃させない。M30の施設破壊／共通同ラウンド全滅は即時敗北。M02は護衛の生存に関係なくボス撃破で勝利、R8で時間切れ。M30はR16終了まで勝利せず、施設生存・ボス撃破・送信のANDを評価する。
- M30の増援は既存のR7/R12配置処理を使用し、信頼済みユニット生成関数を要求する。未解決の機体定義を勝手に補完したり、増援を黙って省略したりしない。
- `src/client/games/robot-tactics/BattleCoreView.ts`：実HP/EN/装備・生存機体・現在小隊・最新結果から既存の戦闘画面モデルを投影する。1小隊は1行動枠、命中は攻撃IDごとに別パルス、2マス施設でもダメージ数字は各攻撃1つ。合法候補と次の順番は信頼済み呼出元の入力で、画面で推測しない。
- 状態復元はHP/EN、位置・盤面・占有、行動枠／EN開閉、撃破待機列、ボス武器・指揮効果、M30施設・データ・増援領収、AI参照の整合を検査する。入力・失敗した同時バッチを変更せず、古い手番・攻撃ID再利用を拒否し、確定済み行動IDは再適用しない。
- 狭い画面／フォント差でサマリーの「閉じる」が44px未満になる問題を対象E2Eで検出し、最小幅44pxを指定した。

## 接続契約と未実装の境界

この状態APIは**内部の信頼済みシナリオ・スケジューラ・解決済み攻撃向け**で、クライアント入力の出撃承認や全攻撃の合法性判定ではない。全NPCの確定構成／所有・CAP検査、完全な行動候補生成、状態異常・追加パーツ・連携・迎撃／反応・逐次2武器コンボ・軽量小隊の共同移動、全ミッション目標を統合した実戦runtimeは後続。本体`apps/robot-tactics/main.ts`のruntime未登録と出撃ガードは維持する。仮エンジンによる正規ミッション起動は追加しない。

射程距離方式は引き続き未確定。SPDの降順グループは検査できるが、同SPDの順、行動中のSPD変化をいつ反映するか、混成小隊の集約を自動決定しない。小隊の同時共同撃破時のEN加算先も既存資料に確定規則がないため、該当ケースは明示的な上位方針がない限り原子的に拒否する。最後に列挙した機体や全員へ無断で配らない。軽量機のEN／移動型など未解決定義も出撃時の既定値にしない。

M02/M30の目的アダプタだけを接続し、M22/M27など他ミッションの複合条件は採用しない。新しい保存形式をアプリへ登録していないため、既存進行セーブやバックアップの形式変更・migrationはない。

## 検証

対象Unitは337件／28ファイル（今回36件を追加）。追加分は状態・目標29件、画面投影3件、保存接続smoke4件。strict型検査と本体・保存fixture・戦闘fixtureの独立ビルドを実施する。

保存接続smokeは、実装済み共通の装備値・武器ダメージ・独立射程／射線・HP/EN・ボス撃破から既存`RobotOfflineSession`の報酬確定までを通す。直接操作／友軍／敵の各待機を1行動ずつ保存・再開し、行動やENの再適用、二重報酬、保存失敗で未確定状態の公開、破損したCoreの上書きを防ぐことも検査する。

テストの順番・距離関数・近撃破のHPチェックポイント・一部位置・軽量機EN100・参照Lv1は**明示的なコンポーネント用入力**であり、正式ルール／正式なNPC定義や難易度を採用するものではない。M30の送信テストも取得／送信間の全合法移動をシミュレートしたものではない。全機のAI・EN・経路・撃破を通した実ミッション勝率検証とは区別する。テスト用runtime／factoryは本体に含めない。

既存PC1280×800／スマートフォン390×844の通信遮断ブラウザ検査は、保存・ホーム8件、戦闘表示36件を対象とする。360×640のタッチ／44px操作も対象。今回のCore接続は上記Unit/smokeと画面投影テストで検証し、ブラウザの既存fixtureを実ミッションへ見せかけない。Windows検証機はオフラインのため未実施。スマートフォン実機での導入・画面消灯／プロセス終了は配布方式決定後の検証として残る。

次は独立して進められるカスタマイズ／育成／性能チェックと、残るCore行動resolverの実装。配布方式・バランス・ルールはこの工程で再決定しない。本番deploy・migration・PRマージは行わない。
