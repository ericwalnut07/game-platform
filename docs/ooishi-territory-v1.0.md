# 大石のテリトリー — Web試作版 ルール v1.0

## 対応モード・ルール選択

- 1人用：1台で全席を操作するホットシート。AI対戦ではない。「1手戻す」「同じ設定で再戦」「設定変更」に対応。ブラウザ内で進行し、サーバーの部屋は作らない。
- オンライン：選択した2〜4人の別端末対戦。ホストが部屋を作成するときに設定を選び、同じ設定で参加人数が揃ったら開始。再接続・再読み込み・同室再戦は共通プラットフォームを使用。オンライン中の1手戻すは不可。
- gameId: `ooishi-territory`、rulesVersion: `1.0`。アプリ版 `0.11.1`。
- 2人の標準：8×8、大2中3小5、ムーンボレー1回、固定順。
- 3人の標準：9×9、大2中3小5、ムーンボレー1回、巡回順。
- 4人の標準：10×10、大2中2小4、ムーンボレー1回、均等巡回順。
- 標準では初手大石、最終ラウンド大石禁止・ムーンボレー禁止（案B）、中石は大石圏内または小石隣接に配置。標準設定以外はルール比較のため試遊版と同じ選択肢を残す。

選択項目：プレイ人数2〜4、盤面7〜11、持ち石（大1〜5、中0〜6、小1〜12）、ムーンボレー回数0〜2、手番順4種、大石禁止ラウンド数0/1/2/4、最終ラウンドのムーンボレー3種、中石配置条件2種。盤面のマス数を持ち石合計が超える設定などは開始前に拒否する。対戦の人数は部屋作成後に変えない。

## 盤面・得点

石自身のマスは持ち主が確定支配（背景は持ち主の色）。周囲へは大石5×5（中心以外24マス）、中石3×3（中心以外8マス）、小石の上下左右4マスに各1の影響力を与える。プレイヤー別に合算し、最大のプレイヤーが1マス1点を得る。最大値同点・全員0は白い中立マス。石が置かれたマスでも周辺石からの影響力濃度は正しい値を表示する。

盤面の各マスには全員の数値を常時表示する。4人の場合は左上＝青、右上＝赤、左下＝黄、右下＝緑で、巡回順に影響されない。スマホも同じ配置。拡大スライダーと選択マスの数値を大きく表示する詳細欄を備える。

手番は盤面上部の大きな色付き表示、盤面直前の表示、配置操作エリア、および現在プレイヤーの強調カードで確認できる。1人用は「青の手番」等、オンラインは本人に「あなたの手番」、それ以外は色・プレイヤー名を表示する。ゲーム進行やルールは変更しない。

## 石の配置と特殊行動

大石は任意の空きマスに自由配置。中石は自分の大石の勢力圏内、または自分の小石に上下左右で隣接する空きマスに配置する。中石の影響範囲だけを根拠に中石を直接接続することはできない。小石は自分の大石・中石・小石の影響範囲内に配置する。相手の支配地域でも自分の配置条件を満たす空きマスであれば合法。

特殊行動「ムーンボレー」は、通常の小石配置ができない自分の影響範囲外の空きマスに小石を置く（小石1個と使用回数1回を消費）。置いた小石は通常と同様に影響力を生み、そこへ中石を接続できる。内部JSON識別子は従来互換の `exp` を維持する。「遠征」から変更するのは表示名のみで、効果に変更はない。

## 案B：ゲームの始まりと終わり

全員の初手は大石必須。以後は合法な石から自由に選ぶ。最後から2手目に大石が残っていたら、その手番は必ず大石を置く。最終手番は大石・ムーンボレー禁止。使わなかったムーンボレー回数は失効。大石を禁止するラウンド数などを試験用に切り替えても、初手大石の基本ルールは維持する。合法配置が1つもない場合に限ってパスし、全手番終了で支配マスの最多者が勝利。同点首位は共同勝利。

## 通信・状態・保護

Coreは純粋なTypeScriptの計算関数。オンラインではDurable Objectだけが正しい盤面と手番を持ち、認証済み接続からプレイヤーを決め、クライアントが送るplayerIdを信用しない。各プレイヤーのViewは全員の石・濃度・残り石を公開し、合法配置先は本人の手番にのみ与える。requestIdの重複防止、phaseVersion、スリープ復帰、切断からの復帰は共通基盤を使用。

D1は既存の `playtest_matches` / `playtest_events` に新gameIdで記録する。開始時のルール設定、ゲームの操作と終了結果（支配マス・勝者・中立マス）を後で分析できる。既存テーブルを再利用するためmigrationは追加しない。『ポンはいない』の分析対象はgame_idで分離する。

## 検証項目

配置条件・影響濃度・確定支配・同点中立・ムーンボレー経由の中石・案Bの大石強制・人数別巡回・2/3/4人の完走・同点勝利をUnitとsimulationで確認する。オンライン2人の部屋作成〜ゲーム終了・本人以外の行動拒否・reload/reconnect・スマホ四隅表示・横スクロール防止をChromium E2Eで確認する。共通基盤変更のため既存2作品の検証も標準 `npm.cmd run verify` で実施する。

GitHub PRはWindows検証とGitHub Actionsの成功後にマージする。本番deploy・remote migrationは明示依頼がある場合のみ実施する。
