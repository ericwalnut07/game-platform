# 商都開発 v0.2 常設NPCと任意の改善用ログ

既存v0.2とPR #10へ追加する機能。商都開発の得点・費用・カード・建設条件と、ポンはいないのCoreは変更しない。

## 常設NPC

ホストがロビーで標準型・生産重視型・商業重視型・開発重視型を追加、種類変更、削除できる。同種の複数配置も可能。人間とNPCの合計4席、すべての人間ゲストの準備完了で開始する。開始後の席は固定。NPCにはログインセッションを発行せず、ホスト移譲対象にも含めない。

`src/games/commercial-hub/npc.ts`は本人向け`HubView`だけを受け取る決定的な共通評価エンジン。プロフィールの重みと建物構成の目安を使う。建設目標をフェーズ間で固定したり、資源を強制予約したりしない。標準型は資金8未満から現金を高く評価する。生産型は在庫・生産力が販売力を上回る場合に商業能力を補う。公開済みの将来商機へカードを残す価値と現在の報酬期待値を比較し、信用収縮の逆転にも対応する。

最終ラウンドの投資は、通常のCoreと同じ企業価値関数を公開盤面の候補へ適用して増分を計算する。投資パスの最高候補評価・資源・輸送費を理由に残す。商業型・開発型は外部試験版のプロフィールを基礎とする。ロジック版は`0.2.1`。

サーバーのGameModuleが450ms間隔で一手ずつ処理する。判断は実行時の最新状態で再計算し、人間と同じCoreの合法手判定を通す。従来の60秒切断BOTとは別で、常設NPCに切断BOTを重ねない。Durable Objectの直列処理と既存requestId重複排除を維持する。

## 交渉の未確定ルール

**既存v0.2に、NPCから人間への提案の回答期限の秒数は規定されていない。今回も未確定。**

実装上の都合で期限を確定しないため、`HUB_NPC_TRADE_RESPONSE_SECONDS`に既定値は設けていない。ルール責任者が秒数を決定するまで、NPCから人間への自発的提案だけを無効にする。人間からNPCへの提案、NPC間の提案と自動回答、その他すべてのフェーズは進む。ユーザーへ90/60/120秒の候補を提示したが、未回答のため採用していない。

決定後に設定すると、NPC→人間の提案は作成時刻と期限を保存し、残り時間を本人画面へ表示する。人間の回答を勝手に選ばず、期限到達で自動拒否する。回答が期限と同時なら期限切れを優先し、資源は移動しない。再読み込み、Durable Object復帰、重複回答でも元の期限を維持する。全員が調達完了した場合の未回答失効は既存Coreの規定に従う。1人1R1提案の制限も維持。

テストの9秒・90秒はテスト用入力であり、運用のルールではない。

## 任意同意とデータ管理

人間の詳細データ提供はロビーで本人が明示的に選ぶ。初期状態はオフ。同意しない人の意思決定記録・本人の手札・非公開交渉は収集しない。同意した本人とNPCについて同じスキーマで、行動前後の本人状態、当時の公開情報、サーバー生成の合法選択肢と費用、確定操作、資源差分、精算・最終結果を記録する。人間の判断理由は生成しない。NPCに限りタイプ、ロジック版、主な評価理由を追加する。

公開盤面には非同意者を含む公開資源・建物・公開カードが含まれる。非同意の人間が当事者となる私的な交渉操作は、NPC側の詳細レコードも伏せ、操作種別と伏せた理由だけにする。すべてのプレイヤーIDを試合内の席番号へ変換し、表示名、セッション、秘密トークンは記録しない。公開履歴・一般API・対戦相手の画面には詳細データを配信しない。

同意を撤回すると以後の収集を止め、その試合で本人の非公開情報を含むレコードを削除する。DBが利用できない場合は削除を再試行する。対戦開始後の新規同意は受け付けない。自動学習やプレイ中の評価値更新は行わない。

`0009_commercial_hub_learning.sql`で専用の2表を追加。既存migrationは変更しない。保存期間は試合開始から30日。取得APIは期限を過ぎた記録を返さず、既存の毎日メンテナンスで物理削除する。対戦中の未保存レコードもこの期限を超えて保持しない。

Durable Objectでは確定ゲーム状態と詳細レコードの送信待ちキューを一括保存する。D1への書き込みはsequenceで冪等化。失敗時はゲームを止めず、失敗件数を保持して再試行する。障害時のキューには件数・サイズ上限があり、欠落を計測する。管理画面の「完備」は試合終了、必要件数と保存件数の一致、欠落なしが条件。削除済みの試合は墓標を保持し、遅延した書き込みによる復活を防ぐ。

管理画面`/#/operations`に試合ID検索、完備状況、JSON取得、削除を追加。既存`ADMIN_TOKEN`認証が必須で、クライアントはトークンを永続保存しない。詳細APIはすべて`Cache-Control: no-store`。

- `GET /api/admin/hub-learning?matchId=...` : 状態検索（省略時は直近100件）
- `GET /api/admin/hub-learning/{matchId}` : JSONエクスポート
- `DELETE /api/admin/hub-learning/{matchId}` : 詳細レコードと未保存データの削除

分析では人間とNPCの選択差から修正候補を作り、固定シードの比較と独立シードの大量対戦を分けて検証する。対戦結果だけで人間の意図を断定しない。
