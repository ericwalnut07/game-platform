## 支払いと大型投資

全カードに必須資金＋自由枠を適用。自由枠は資金・資材・商品を1個＝1枠で組み合わせ、全額資金も可。サーバーが整数・非負・合計・残高・投資手番・市場在庫・都市Lv・最終Rを検証する。requestId/phaseVersionによる既存の二重実行防止を使用する。

- 事業拡張計画（10）：翌Rから通常21枠の外に専用地区1枠。無料建設なし。建設と上位化は投資各1回、資金3＋自由2、地区補正・輸送・監査なし。通常6棟＋専用1棟。同系統3棟には専用建物も含む。他社建設不可。所有と建物・上位化状態は全員公開。
- 物流独占契約（10）：翌Rに自社路線のあるスートを1つ固定。2地区のうち自社路線がある地区だけ強制使用し、後から敷設した路線にも自動適用。公共・他社路線への迂回不可。封鎖を優先し、封鎖中は当該輸送行動の合法候補なし。輸送費はR末精算。専用地区は対象外。
- 公共事業優先契約（9）：毎R指定事業の独占を維持し、所有者の初回拠出で必要資源1個削減。同じ事業の連続指定不可。商機軽減と併用可、0未満にはしない。複合枠は既存の資材優先順、監査費は対象外。使用済みRをStateに保存する。
- 監査受託事業（8）：他社の実際の監査費を受領。自己分は見積もり段階で免除し、免除分の銀行収入なし。建物稼働・上位化・路線敷設・拠出に適用。監査官なしでは市場へ出さない。
- 広域物流規制（5）：価格のみ変更。封鎖条件・発動・不発条件は維持。
- 産業高度化計画（8）、高度設備導入（8）、産業活動奨励金（5）、技術使用料請求（5）、公共事業権益買収（5）：既存効果維持。

独占契約の発動時に自社路線がない場合の既存仕様は維持する。当Rは対象なし、カードを保持し、翌Rに未指定の場合のみ再選択する。指定後のスート変更は不可。

## フェーズと公開状態

トリック・ビッド・監査官 → 大型投資の経済前効果 → 公共市場・交渉 → 建物稼働 → 大型投資の投資前効果 → 投資2巡 → 精算。

Core内部のPROCUREMENT識別子は市場・交渉、PRODUCTIONは3系統の建物稼働として再利用する。旧版では従来の意味を保つ。調達→工業→商業→未使用調達など任意順に行動でき、全員がPRODUCTION_DONEを確定すると進む。

技術使用料は経済前に通常使用を消費。設備の追加使用を残す。奨励金は稼働後の実使用回数（技術使用料・追加使用を含む）で算定。公共市場と交渉の使用制限を変更しない。

画面は公開資源・接続・所有資産・操作確定状態、自分だけの精算見込みと価値、現在の操作案内を表示する。マップ選択で手番タブの対象建物・地区へ移動。大型投資の資源配分と建物稼働は確認後に確定する。直近履歴・過去Rのフェーズ別結果・詳細ログは確定イベントから作る。未公開ビッド、他社手札・価値・交渉条件は公開しない。

## 記録と比較

既存D1サマリーとprivate R2イベントアーカイブを継続する。MAJOR_PURCHASEDのcost/freePayment、BUILD/UPGRADEの対象とquote、輸送chargeのforcedMonopoly、PRIORITY_DISCOUNT、AUDIT_WAIVED、BUILDING_USED/ROYALTY_OPERATIONの順序から分析可能。逐次D1書込みや新migrationは追加しない。

`node scripts/run-hub-trial4.cjs --games=320 --output=trial4-comparison.json` はA（trial 3）、B（大型投資のみ）、C（稼働のみ）、D（両方）の計1,280局を実行する。`--condition=A`などで単条件実行も可能。2終了方式×2トリック方式×監査官有無を均等にし、シード・席順・NPC構成を条件間で一致させる。試験専用のnext.changesはクライアント設定から受け付けない。

資源産出・消費は確定イベントの直接変換、監査受取・免除、独占輸送の実精算額を分けて測る。カードの不発はイベント件数（恒久カードの対象なしは複数Rで発生し得る）。NPC結果は人間の最適戦略を示すものではない。

検証の確定結果は別のvalidation報告に記載する。本番deploy、遠隔D1 migration、Secret変更は実施しない。
