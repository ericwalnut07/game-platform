# 商都開発 v1.0準備 Work 2：商機と8トリック

Work 1のPR #19（merge `a1f9768a6ea31639acfc003bee0a5f5d3260bc72`）を基礎とする。正式版への一本化・大型投資UIの変更・アプリ0.21.0化・本番操作は別工程。

## ルール

開業は6トリック、3位資金1を維持。通常は5トリックで報酬・切札・選出方式を維持する。

Lv3到達翌Rの特別消費ブームのみ8トリック。4人に8枚ずつ配り、全32枚を消費する。Must Follow、商業切札、時計回りのリード交代を維持し、全員が2回ずつリードする。

| スート | 各1回の商機 |
| --- | --- |
| 商業 | 販売・販促 |
| 工業 | 加工・増産 |
| 調達 | 仕入れ・大量仕入れ |
| 行政 | 開発・公共事業 |

全8種類を重複なく既存shuffleで並べ、特別資材は登場させない。通常相場の袋に含めず、従来どおり1回のみ。

公共事業商機の1位は必要資源1削減＋拠出成立後に資金1、2位は通常拠出成立後に資金1、3・4位はなし。新1位の権利を `DISCOUNT_REBATE` として保持し、実際に拠出してから支給する。旧 `DISCOUNT` は軽減だけのまま。監査費・支払い可能性は還元前に検証し、還元を先払い資金として扱わない。公共事業優先契約との割引を併用し、複合資源枠にも1資源ずつ適用、費用の下限は0。監査費は軽減しない。

## 内部バージョンと旧状態

`createHubV1WorkState(matchId, players, rng, config)` はWork 1の `constructionRule: "v1-distinct-suits"` に加え、`opportunityRule: "v1-work-2"` を付与する。`v1Opportunities(state)` で商機変更を判定し、保存・復元・view投影で保持する。

既存0.5、trial 1〜4、Work 1時点の状態には商機バージョンがないため、特別ブーム6T・特別資材・旧公共事業報酬を維持する。部屋設定には切り替えを追加せず、通常の新規NEXT起動もtrial 4のまま。

ビッド通信の受付上限は8。実際のラウンド上限はreducerが商機数で検証するため、旧5T／6T対局は7・8の宣言を拒否する。NPC予測・ビッドUI・監査官集計は可変商機数に対応する既存処理を利用する。
