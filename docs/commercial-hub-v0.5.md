## 監査官判定

R1未配置。R2以降、すべてのトリックとビッド結果の後、経済活動の前に決める。

1. 商機報酬の対象順位に入らなかった回数を数え、最多を選ぶ。信用収縮では逆転した `rewardRanking` を使う。通常は3・4位。既存の開業商機・特別資材は3位にも報酬があるため3位を獲得に含める。
2. 同数なら実際のカード順位の合計が最大（平均が最も悪い）。全員同じトリック数なので整数の順位合計で比較し、浮動小数点による同点判定を避ける。
3. なお同じなら、そのRの最初のリードから時計回りで最も近い席。ラウンドをまたぐ既存リード循環から `roundTrickStarter` を保存し、投資開始者や最初のゲーム開始席とは混同しない。

任意の販売・加工・仕入れを辞退した場合や支払資源不足でも、商機を獲得した順位そのものは変わらない。配置者、各社の未獲得回数、順位合計/平均、時計回り距離、使用したタイブレークは保存・公開する。

商業＝市場/ビジネス街、工業＝工房地区/工業団地、調達＝倉庫地区/港湾、行政＝再開発地区/新市街。行政地区の既存 `suit: null` は建設ルールを変えず、監査判定でのみ行政系統に対応させる。クリック/タップした候補の2地区を強調し、確認後に移動する。配置放棄不可・据え置き可・決定まで前回配置を維持。配置者自身にも費用が適用される。

## 経済・終了・NPC

建設は通常建設費/地区割引/開発割引を維持し、監査費・輸送費を課さない。上位化・建物使用の輸送0/1/2とR末精算、路線建設基本費、銀行への監査費資金1は維持。物流センターは数量ではなく使用1回を消費する。UIでは資材3を標準、可能な少量モードを選べ、監査/輸送込み費用を確認できる。

Lv4初到達Rと確定した最終R/理由をStateに保存する。一度確定した予定は変更しない。未確定中の画面は最長R12を表示する。最終Rも仕入・生産販売・投資2周・後払い精算・都市発展判定を行ってから最終結果を出す。Lv2/3/4初到達Rを記録する。R12未到達の理由も最終精算時に確定する。reload/reconnect、DO復元は同じStateを読み出す。

NPC4タイプ・基本構造は維持。新しい供給量/資源価格、必要数量の在庫予約、拠出増分得点と完成見込み、監査費、建設輸送なし、残りR数、資材の在庫処分を評価する。ビッド期待値は従来の商機期待値/温存価値との複合評価を維持。監査官配置権の期待値は最後の行政勝利から、公開済み全トリックの未獲得成績と順位見込みへ変更。未知の手札・未公開ビッドは参照しない。旧外部v0.2比較モデルは互換なしとして実行を拒否し、現行NPCの比較には利用しない。

## 通信・ログ・互換性

GameModule型・RoomObject・WebSocket・再接続・requestId重複防止・再戦・ホスト移譲・部屋寿命・maintenance/health・既存ゲームの実装は変更しない。既存ビッドの秘匿性を維持する。

D1 migrationは追加しない。既存 `commercial_hub_matches` / `commercial_hub_events` / 共通 `playtest_matches` を使い、`app_version`・`game_id`・ルール版を分離する。`ROUND_SETTLED` のD1専用payloadに、R/終了予定と決定理由/Lv初到達R、および各社の資源・下位/上位建物・路線・企業価値内訳・事業別拠出数を含める。`AUDITOR_RIGHT` は配置者/成績/タイブレーク、`AUDITOR_PLACED` は対象系統を記録する。最終順位と値は既存summaryにも保存する。

Rごとの各社企業価値はサーバーの `roundStatistics` に保持し、D1書込時にだけイベントへ合流する。Player Viewのイベントに混ぜず、他社価値・手札・未成立交渉を漏らさない。任意同意付き学習ログ、保持/削除の仕組みは維持する。

旧0.4の進行中Stateを途中で新ルールへ変換しない。既存の版不一致ガードを0.5へ更新し、新部屋/再戦で新ルールを使う。本番公開・本番D1・Secret変更は今回実行しない。旧版の対局を終了してから公開する運用上の扱いは別の公開工程で確認する。

## 検証

Unitは既存回帰を新コスト/出力量/配置者へ更新し、v0.5境界テストを追加。4条件の比較は `npm run simulate:hub-rules -- --games=100 --seed=7823 --output=...` で、同じ25シード×4席順ローテーションを各条件に使う。レポートはR10/11/12割合、Lv到達R、NPC勝率・価値内訳・建物構成/上位化/拠出、Rごとの経済推移、監査分布と費用/資金不足/投資パスを含む。異常手・デッドロック・負の資材/商品・不正得点は失敗として終了する。

E2EはPC/モバイルの通常4人完走・4設定・混合NPC・秘匿/再接続/再戦を維持し、建設の輸送選択なし、系統監査の候補、最終R決定後reload、D1各R経済ログを検証する。正式確認はWindowsの対象commitで `npm.cmd run verify`、PRのCI/Mobile E2E両方。結果は別検証報告に記録する。
