## 盤面・初期配置

盤上は1〜20。**20は通常ポイントで、次の21がゴール**（2026-10-19ユーザー確認）。両者とも番号が増える方向へ進む。配列indexはポイント−1、スタックは下から上の順。

各自は大2／中3／小3、計8石。A・Dは相手の石を含む。

|グループ|下→上|先手|後手|
|---|---|---:|---:|
|A|自大・敵中・自小|1|2|
|D|自中・敵小|3|4|
|C|自中・自小|7|6|
|B|自大|10|11|

開始席を変更する場合、先手の配置もその所有者へ割り当てる。

## 手番と移動

1. `AWAITING_ROLL` でROLL。呼出側から注入された乱数源が1〜6を2回返す。送信データの出目は使わない。
2. `MOVING` で自分の石と使用する出目スロット（0／1）を選ぶ。
3. 選んだ石とその上の全石を、所有者を問わず同時に運ぶ。下側は元のポイントへ残る。
4. 移動先は現在地＋出目。途中のポイントは着地条件に関係しない。
5. 使用したスロットをUSEDにし、残りの出目の合法手を再計算する。

出目の使用順は自由。同じ石を2回動かせる。ゾロ目もスロット2個、2回分のみ。両方または残りのどの出目にも合法手がなければ、その残りをPASSEDにして相手のROLLへ進む。任意のパス操作はない。

一方の出目で他方の着地点を空けることがあるため、使用不能な出目も、別の合法手が残っている間は捨てない。合法手を1回適用するごとに再評価する。

着地は運ぶまとまりの最下段で判定。下側の所有者は不問。

|最下段|通常ポイントの着地先|
|---|---|
|大|空きのみ|
|中|空き、または最上段が大|
|小|空き、または最上段が大／中|

## ゴールと終局

21へぴったり到達した場合、運んだ全石を各所有者のゴール済みリストへ加える。21超過は不可。自分の8石すべてがゴールしたら即時勝利し、残りの出目は使わない。相手が運んだ結果でも同じ判定を行う。1回の移動で両者8石なら引き分け。

Coreは元のStateを書き換えず、新しいStateを返す。終局後・手番外・不正ポイント／層／出目・相手石選択・使用済み出目・ROLL前の移動・同一手番の再ROLLを拒否する。移動先はCoreで算出し、送信されたtoを採用しない。プレイヤーID認証はオンラインGameModuleを追加するフェーズ9で扱う。

## フェーズ7：標準NPC

`src/games/ooishi-caravan/npc.ts` に標準NPCを追加。

- `chooseCaravanNpcAction(state, seat?)`: ROLL、合法なMOVE、または手番外／終局後のnull
- `analyzeCaravanNpc(state, seat?)`: 最初の操作と、その時点の出目で計画した移動列、評価値、探索数
- `caravanNpcFeatures(state, seat)` / `evaluateCaravanNpcState(state, seat)`: 調整・simulation用の評価

実際に振られた現在の出目について、全合法な1手目と、その後の全合法な2手目をCoreで適用し、手番終了／終局時の評価が最大の手順を選ぶ。通常は自石最大8個×2出目＝根最大16手、その後最大8手で、適用局面は最大144、深さは最大2移動。枝刈りで候補を落とさず、ゾロ目の両スロットもCoreどおりに扱う。各移動の確定後に現Stateから判断し直す。

未来のサイコロを振って読んだり、実乱数源を消費したりしない。将来の配置しやすさは1〜6の各面を仮定した単出目のCore合法手を用いて評価し、NPC専用の移動ルールを作らない。相手の未知の2出目や応手そのものは探索しない。同評価ならCore列挙順で決まり、同Stateに対して再現可能。

係数はゲームルールから分離した `CARAVAN_NPC_TUNING`。

|項目|係数|内容|
|---|---:|---|
|ゴール済み数|18|早いゴールの価値|
|全石の進行|0.8|ゴール済みも21として計算|
|最も遅い石の残距離|−0.6|後方の取り残しを抑える|
|自石の運搬ペア|1.2|同じ塔で運ぶ効率|
|相手を載せた運搬リスク|−0.8|相手の進行を助ける負担。終盤ほど増える|
|相手の下石に運ばれる可能性|0.5|混成塔の位置関係|
|将来の合法手数|0.4|6面平均。相手の合法手減少も評価|
|自石と合流する候補|0.5|6面平均。大中小の合流|
|ぴったりゴール候補|3|6面平均。運ばれる自石数も含む|
|ゴールできる出目の種類|0.8|終盤の待ちの幅|
|相手大石の着地難／自分大石の着地難|±0.7|Core合法手から算出。遮断・超過を含む|
|勝ち／負け|±1,000,000|終局は通常の評価項目より常に優先。引き分け0|

すべて自分と相手の差で評価する。実際に相手をゴールへ運ぶ利敵効果は相手進行・相手ゴール数にも反映される。混成塔の維持と離脱は固定方針にせず、全手順の結果で選択する。

## フェーズ8：PC／mobileソロUI

TOP → 1人で遊ぶ → 大石のキャラバン → 人間対標準NPC。先手は自分／NPC／ランダム。ソロはブラウザ内のCoreで進み、乱数はcryptoから取得する。オンラインの権威処理はフェーズ9で実装する。reloadで設定へ戻り、この段階では永続セーブを追加しない。

左側は手番、ダイス画像2個、ふるボタン、出目の使用状態、両者の色とゴール数、選択中の石、移動情報。右2列は上から10/11、9/12、…、1/20のU字盤面と、20の次のゴール21。操作欄はstickyでスクロール中も利用できる。方向／サイズの常設説明は置かず、遊び方は展開式。

自分の石を選ぶと、その層と上の敵味方全石を強調。出目に対応する合法移動先をCoreから表示し、移動先をタップ→左側で確認して確定。出目変更で未確定の移動を解除する。使用済み／現在使えない出目を操作できず、残りが使えない場合はCoreの自動パスを表示する。

横バーはラインのStoneBarと既存の描画CSSを直接再利用。上段だけ大中小の文字を表示し、バーより広いタップ領域を取る。汎用コンポーネントへの抽出は予定どおりフェーズ11で重複を確認して行う。

NPCはROLLと各MOVEを約1000msずつ空け、思考中は人間操作を無効化。直前の操作に移動元・移動先・運んだ石数・パスを表示する。設定へ戻る／再開／画面退出時は予約された古いNPC操作を解除する。結果、同時ゴール引き分け、再戦に対応。

## フェーズ9：オンライン人間2人

`module.ts` は既存Coreを使い、認証済みsocketのplayerIdから席を決定する。受信したplayerId・seat・出目・toは採用しない。ROLLはサーバーのcryptoRandomを注入する。ROLLとMOVEのどちらもrevisionを1増やし、phaseVersionで古い操作を拒否する。

ロビーではホストだけが開始プレイヤー指定／ランダムを変更できる。サーバーが毎回開始順を確定し、選択者不在時は現在のホストへフォールバック。先手の初期配置をseat 0へ割り当てる。再戦は指定設定を保持、ランダムは再抽選。同じ順の再出現は許容する。

RoomObjectの直列化・永続requestId重複防止・phaseVersionをキャラバンにも適用。ROLLの再送でも出目を振り直さず、MOVEの再送でも出目を再使用しない。有限個の石と現在状態のみを保存するため、ラインの千日手履歴用分割保存は不要。人間切断時にNPC化せず、同じ席・盤面・出目・使用状態でreload／reconnectする。

オンラインUIは実対戦相手名と所有者色を表示。待機中にNPC思考とは表示しない。offlineでは操作を無効化し、相手切断時は復帰待ちを案内。終局時の再戦はホストのみ。ソロNPCの既存動作は維持する。

既存D1のplaytest_matches／playtest_eventsを使用。CARAVAN_CONFIGにrulesVersion・設定・確定した席順、CARAVAN_ACTIONにrevision・actor・ROLLまたはMOVE・確定出目／使用状態・移動先・運搬石・次席・ゴール数、CARAVAN_RESULTに最終結果・手数・ゴール数を保存。app_versionは0.28.0。Unitでログから全対局を再生し、最終盤面が一致することを確認する。新規migrationなし。

対象検証はtypecheck、キャラバンCore/NPC/Module/Room/ログ・registry・共通接続テスト、migration整合、build、キャラバンsolo＋onlineと共通solo入口のPC/mobile E2E。オンラインE2Eは実部屋で指定／ランダム、ゲスト設定拒否、偽装actor拒否、ダイス再ROLL拒否、実UI移動、重複操作、使用中の出目を保持したreload／offline／transport切断復帰、全局完走とD1保存、ホスト再戦を確認する。複雑なゴール分岐は対象UnitとソロUI fixtureで補う。本番へテスト専用状態注入機能は追加しない。
