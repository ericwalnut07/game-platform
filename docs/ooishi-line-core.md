# 大石のライン：Core実装状況

gameId予定: `ooishi-line`。2人用・4×4、各自大4／中2／小1。

## フェーズ2で実装済みの確定部分

`src/games/ooishi-line/position.ts` はPure TypeScriptの局面モデルと判定関数。

- 16マスのスタック（下から上）、所有者・サイズ・両者の手持ち・次手番。
- 大4／中2／小1の初期状態。
- 最上段だけを見て、同一所有者の大中小が1個ずつ並ぶ縦横連続3マスの勝利判定。全サイズ順序を許可し、斜めは数えない。
- 両者のラインが同じ結果局面で成立していれば引き分け。
- 全マスの全層・順序・所有者・手持ち・次手番を含む局面キー。
- 初期局面を1回目として記録し、同じキーの3回目で千日手引き分けを検出。履歴更新は非破壊。

局面履歴は各合法手の完了後、次手番を更新した状態を1度だけ登録する想定。
未確定の配置・移動条件を回避して操作を実行するAPIは設けていない。
GameModule／カタログ／画面への登録もまだ行わず、未完成ゲームを公開しない。

## フェーズ2の残り

旧A改の大石↔小石の役割・個数・制約を入れ替える前提は維持する。
確定している配置条件は「小石は中石の上にのみ重ねられる」。
旧A改全文がこの引継ぎや現行コードに含まれていないため、以下は確認後に実装する。

- 大・中・小それぞれの空きマス配置可否、同サイズ・異サイズの積層可否。
- 相手石を土台にする場合の制約。
- 盤上移動の方向・距離・移動先条件。新規配置と移動で条件が異なるか。

これらが確認できたら、手持ち配置・任意の自石と上層全体の移動・下層露出・合法手生成・手番更新・終局処理を統合し、対象Unitで完成させる。
Coreの合法手確定前にNPC、UI、オンラインは実装しない。
