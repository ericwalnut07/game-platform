# 商都開発 商機画面のコンパクト化

基準：main 34cf2f75766a4b16088f785cd60c016006d6becf（PR #42統合後）。

TRICK / REWARD / TRICK_RESULTだけ、資源バー・商機列・場札・手札をコンパクト表示する。場札は4人を2列×2行で固定し、名前・カード・確定順位・公開された報酬情報をまとめる。確定前の順位は表示しない。商機の詳細はキーボードでも開閉できるダイアログ。既存の手札提出・報酬選択アクション、サーバー判定、ルール・得点・NPCは変更しない。

ビッド宣言画面は従来どおり。トリック中は本人の宣言・現在の勝数・残り数を表示し、全員の詳細は展開する。view.bidsが非公開なら他人の数値は表示しない。ビッド結果は既存のBID_RESULT時点からラウンド末まで確認できる。場札欄には「ビッド実績＋1勝」を追加しない。

## 公開データによる表示と制約

- 順位は同じラウンド・トリックindexのtrickResults.rankingを利用。信用収縮の報酬順位はrewardRankingを別表示。
- OPPORTUNITY_REWARDから即時獲得資源を表示し、権利は同イベントの商機と確定報酬順位に対応する既存説明を表示する。
- DIRECT_REWARDに記録されたcost/rewardの差だけを実際の資源変化として表示する。他のトリックのイベントを流用しない。
- 現在のcurrentPlayerは「選択待ち」。他人のrewardChoicesキューは公開されないため、まだ使用ログがない他プレイヤーについて、辞退済みか選択待ちかを推測しない。
- TRICK_RESULTで報酬処理が完了し、当該トリックの4人分の獲得ログがそろっている場合、任意交換の使用ログがなければ「使用せず」。資源不足で選択権が生じなかった場合もここに含まれる。**辞退と資源不足の内訳は公開データから区別できない。**
- ログ欠落時は「記録を確認できません」とし、未使用と断定しない。後からの再接続も同じ公開データから再構築する。
- 処理中の各人の確定状態・未使用理由まで厳密に区別するには、選択処理結果（辞退・使用不可を含む）の公開イベント、または公開ステータスの追加が必要。今回のUIのみの範囲ではサーバーを変更しない。

## 検証

実Layout（サイトヘッダー・共通余白を含む）のfixtureでPCとスマホ縦画面を検証。390×844を基準に、主要情報が画面下部のタブに隠れないこと、操作対象が44px以上であること、横はみ出しがないことを計測する。8商機・8枚手札、進行中、確定順位、報酬選択、完了、保存復元、ビッド非公開・公開・結果を確認する。

Windows総合verify・GitHub Actions・実画面の最終結果と対象SHAは専用PRに記録する。本番公開は行わない。
