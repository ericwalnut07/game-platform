# 戦闘Core詳細設計08 — 状態管理・保存・検証

## A 機能境界
戦闘Core、編成Core、育成/報酬Core、静的データ、保存アダプタ、UI/演出を分離。Coreは現在状態とコマンドから次状態/イベントを決定する純粋処理。予測・合法手・AIと共通関数を用いる。UIはコマンド送信と確定結果表示のみ。時刻、乱数、DOM、保存APIはCoreから分離。現在は必中・決定論、将来乱数導入時はシード/状態を保存。データ定義は安定ID、表示名を参照キーにしない。武装/装備/功績/敵/ミッションの原表欠損は未確定として扱い、MVP採用分の必須データが欠ければ検証失敗。
## B セーブ状態
1進行データ＋直前正常スナップショットを標準。SaveEnvelope: gameId=monster-wars, schemaVersion, rulesVersion, contentVersion, saveId, revision, payload, checksum（破損検出用、改ざん防止を保証しない）。CampaignState: 解禁ID、難易度×ミッション初回クリア記録、勝利回数、未配分EXP、兵種別累積EXP、モデル別功績累積値、編成/装備、次battleId、報酬確定ledger。派生Lv・最大HP等は原則再計算。BattleState: battleId、開始時編成/能力/武装/難易度/ミッション定義とルール版、phase/round/陣営ターン通番/段階R、revision/eventSequence、全実体（撃破済みも集計保持）、位置/向き/層/HP/部位/形態、弾薬と支援回数、行動権/移動履歴、状態・耐性期限、CD/迎撃/予告固定範囲/予約、地形変更、増援ledger/予約/延期/生成/分裂、条件進捗、功績一時計数、終端結果と報酬receipt。占有index/到達範囲/AI候補等は再構築。戦闘中の部隊能力は開始時固定、戦闘内補正のみ可。編成変更は戦闘外。
## C 保存トランザクション
自動セーブ: 新規開始、編成/装備変更、EXP配分、戦闘開始、各原子的行動（移動と迎撃全解決含む）、AI各原子的行動、陣営/ラウンド境界、段階移行、終端/報酬確定。行動途中・アニメーション途中の中間状態を保存しない。戦闘終了と報酬確定は同じ保存トランザクション。コマンドにbattleId/revision/commandId、古いrevisionまたは別battleIdは拒否、同ID再送は再適用しない。純粋計算→整合性検証→永続化成功→状態公開/演出。失敗時は旧確定状態保持・操作停止・再試行/旧状態からバックアップ書き出し。保存成功後に演出が中断しても結果は確定済み、再読込は演出を再実行しない。AIは次の合法行動から再開。開始/終了フェーズを保存して開始効果やDOTを再発生させない。
ブラウザ保存はIndexedDBの単一readwrite transactionで進行状態・直前正常バックアップ更新を第一候補とする。file://やAndroidで永続化が利用できない場合は実機確認し、localStorage等の単一キーへの完全スナップショット書込み＋別キーの旧正常バックアップを代替候補（失敗時に旧状態を保つ、複数キーの同時原子性は仮定しない）。起動時に読み書き検査、利用不可なら警告し新規プレイは明示的な一時モード選択時のみ許可。書き出しJSONで保全。複数タブ同一セーブの同時更新はrevision比較による競合拒否を必須（IndexedDBトランザクション内比較。localStorage代替は厳密な同時書込み保証がないため排他を確保できない環境では一方を読取専用/一時モードとする）。ブラウザの保存領域は端末/ブラウザ/オリジン/ファイル位置によって異なり、永続保証なし。単体HTML更新・端末移行の正式手段はJSON書き出し/読込み。
## D 報酬と育成
勝利終端のみ初回/再挑戦判定を難易度×missionIdで行う。battleIdに一意receipt、同一トランザクション内で初回クリアフラグ、勝利回数、EXPプール、功績累積、解禁ID、終端結果を更新。二重読込/ボタン連打/再送/結果画面再表示で再付与しない。初回と再挑戦EXPは排他、個別追加目標は別明示定義がない限りなし。敗北/撤退は報酬0、次戦HP/弾薬/支援全回復。獲得EXPは共有未配分プール、戦闘外で任意の解禁済み兵種に配分、整数、上限Lv50必要累計まで、余りはプール保持、誤操作防止の確定前プレビュー、確定後の再配分不可。功績は勝利時のみ累積更新し次戦から反映、Lv5後も実績記録継続。戦闘中断復帰は同一battleId、新規再挑戦は新battleId。進行中の戦闘を破棄して再挑戦する場合は撤退確認。結果画面の確認操作はreceipt表示のみ。
## E 互換性・インポート
schemaVersionとrulesVersion/contentVersionを分離。正式配布後の旧schemaは段階migration、元データのバックアップを保持、検証成功後にのみ置換。新しい未対応schema/未知gameId/不正参照/範囲外値は拒否。進行中戦闘は開始時ルール/データ版を維持して再開できる場合のみ継続、新仕様へ自動変換しない。旧ルールを同梱できない更新では、進行中戦闘の再開不能を明示し、ユーザーの承認で戦闘のみ撤退扱いにして育成/解禁/過去報酬を保持する選択肢（自動破棄禁止、元JSON保持）。互換性を壊す更新は事前承認。正式版前の試作schema変更も可能な限りmigrationするが互換範囲を配布時明示。インポートはJSON解析→スキーマ/ゲームID/バージョン/参照/状態不変条件/チェックサム→差分概要→置換確認→原子的保存。自動マージなし、現セーブバックアップ、未来版拒否。異なるバックアップ時点を選んだ場合はその時点へ全体復元し、部分的なEXP/報酬合算は行わない。破損時は直前正常候補を提示、無断上書きなし。オフライン単独利用なので悪意あるセーブ編集への完全対策は目的外。
## F 検証計画
01–07の境界テストを仕様IDで参照。Unit: 編成整数COST/互換/成長/報酬、移動旋回層/地形/射線、属性/DEF/丸め/複数マス/部位、状態期限/耐性/支援/補給、迎撃/予告/CD、増援/分裂/勝敗。状態不変条件: 同層占有非重複、HP/弾薬/耐久/行動権範囲、終端後状態不変、功績/報酬一意、参照ID妥当、予測と実行一致。同じ状態/commandの決定論比較。保存回帰: プレイヤー移動後攻撃前、敵AI途中、迎撃中断後、予告準備、DOT/状態期限、増援部分成功・延期、部位破壊/形態移行、ラウンド境界、勝利直後/結果再表示、初回/再挑戦/敗北/撤退、再送/古いrevision、容量不足/書込失敗/競合、壊れたJSON/未来版/旧schema、export→import、旧版戦闘非対応。実装で保存アダプタの失敗を注入、再読込後の最終状態/報酬一致を比較。Smoke: 編成→戦闘→報酬→育成→再挑戦、装備交換で攻略差、育成で難所緩和、立ち回り差。固定AI敗北は原因調査、成功期待テストの無根拠緩和禁止。MVP 3ミッション×E/Nの合法性/推奨育成・装備での実戦確認。PC Chrome/Android Chrome横画面でタッチ、セーブ復帰、JSON移行、オフラインHTMLを検証。配布候補は対象ゲームUnit/smoke/E2E/typecheck/build/CI、生成元コミット記載、他ゲーム全面検証は原則不要。実装・テストは未着手、ブラウザ保存方式の実機成立は未確認。


## 試遊版v1→v2（2026-11-26）
旧進行の育成・編成・履歴・報酬台帳を保持し、クリア履歴に応じて新装備の解禁だけを追加する。旧進行中戦闘のID、手番、行動権、敵枠、属性と成長はrules=1として継続。新規出撃はrules=2。モード・指示・対象ID、オート実行中か終了遷移付きかを戦闘に保存し、再開時は現在の権利から次の一手を再評価する。


## 第2回調整版のv3移行
v1/v2の戦闘は旧敵性能（将来の増援を含む）・勝敗条件で再開。敵図鑑の登録集合には、更新版で自軍に帰属する本体撃破の確定イベントを受けてモデルIDを追加する。勝利報酬と独立し、戦闘状態・育成と同一トランザクションで確定する。旧データから帰属を確定できない撃破は登録しない。
