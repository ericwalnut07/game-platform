# 戦闘Core詳細設計 01 — ラウンド・行動管理
2026-11-25。採用済み design.md / units-and-giants.md / enemy-design.md を参照。以下の新規詳細は提案であり承認前に実装しない。
## 採用済み
陣営ターン制、自軍任意順→敵軍→ラウンド終了。通常ユニット移動1・主行動1、順序自由、移動分割不可。主行動は攻撃・防御・迎撃・支援・待機。SPDなし。通常防御30%、次自軍ターンまで。敵ボスは個体/難易度/形態別の複数主行動、移動1、同一特殊1/R、防御最後、予告準備・発動各1、形態変化で行動回復なし。
## 提案 A 行動管理
- 各陣営開始で生存かつ行動可能な実体に移動権1と主行動権を付与。増援の初回行動は次の所属陣営ターンから（個別例外は後段で定義）。同じ実体の行動間に他実体の行動を挟める。移動権と主行動権は独立。選択解除は消費なし。
- 移動は経路と最終姿勢を一括確定、1回のみ。距離0・姿勢変更なしは移動とみなさない。旋回のみは移動権消費。攻撃後移動可、移動射撃排他の攻撃後は移動権を放棄、移動済みならその攻撃不可。静止条件は旋回も移動扱い。移動後の威力低下武装は移動済みなら補正、攻撃後移動はその攻撃に遡及しない。
- 防御/迎撃は残り移動権を放棄し行動終了。待機は残り全権を放棄。主行動のみ使用済みでも移動可能な場合は未完了。移動のみで終えたい場合は待機。迎撃回数/発動は第6段階。
- ターン終了は全権消費を要求しない。未使用権がある場合は確認表示。明示終了で残権消滅。自動終了はしない。敵AIは全行動完了または合法手なしで終了。
## 提案 B 時間と処理境界
- 第1R自軍開始。各陣営開始→開始時効果→行動→陣営終了、敵陣営終了後にラウンド終了効果（燃焼等）→増援/ミッション条件→次R。勝敗判定の厳密優先は第7段階。状態継続は第5段階で効果ごとの期限を定義し、単純な全状態一括減算を避ける。個体定義の再生タイミングは優先。
- 主行動は一括トランザクション。合法性→権利/弾薬消費→全命中処理→撃破/部位破壊/形態変化→反応/勝敗評価（詳細は後段）。不合法な入力は状態不変。UI演出は確定イベントを再生するだけ。多段攻撃の途中に別ユニット操作を挟まない。
- ボス行動枠は敵ターン開始時の形態で決め、途中の形態変化は残権を増やさない。撃破で未使用権消滅。予告・発動は既存個体の個別条件優先。
## 技術設計（実装前）
BattleState: round, phase, unitsById, actionRightsById, pendingTelegraphs, revision, eventSequence。UnitState: entityId, modelId, faction, anchor, facing, layerMode, hp, ammoByWeapon, partStates, statuses, cooldowns。Core純粋関数 validateCommand / enumerateLegalActions / previewCommand / applyCommand（同じ判定関数共有）。入力に stateRevision と commandId、適用は原子的、重複・古い入力は拒否/既処理結果。数値データとは分離。
