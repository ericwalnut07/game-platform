# 商都開発 v1.0準備 Work 1：建物建設

この文書はWork 1時点の仕様。Work 2以降の内部入口には商機バージョンも追加される。Work 1時点の保存状態は商機変更の対象にならない。最新の内部起動仕様は `docs/commercial-hub-v1-work2.md` を参照。

全8地区で、同一商会の異系統建物を複数建設できる。同一商会・同一地区・同一系統の重複は禁止。再開発地区も同じ判定を使用する。他商会の同系統建物とは競合しない。

地区別枠数・通常21枠・通常6棟・専用地区1棟・全建物を合算した同系統3棟・地区解放・費用・地区補正・輸送・監査・独占はtrial 4のまま。建物IDごとに稼働と上位化を処理し、同じ地区でも独立して操作する。

## 次段階の内部起動方法

`src/games/commercial-hub/v1-work.ts`の`createHubV1WorkState(matchId, players, rng, config)`で新しい検証用状態を作成する。NEXT trial 4を基礎に、状態の`constructionRule: "v1-distinct-suits"`のみを追加する。判定は`distinctDistrictSuits(state)`で統一。JSON保存・復元とサーバーからのview投影で保持される。

本番GameModuleは従来の`createHubState`を呼ぶため、新規NEXTは引き続きtrial 4。設定・クライアントアクションには切り替え項目を追加しない。既存状態を自動変換しない。旧0.5・trial 1〜4はスイッチがないため従来の地区制限（NEXT再開発地区の旧例外を含む）を維持する。

Work 2以降の検証でもこの入口を利用できる。正式1.0への切り替え・商機変更・アプリ0.21.0化は別工程。本番deploy・遠隔migration・Secret変更は対象外。

## 検証

Unit：全地区の異系統建設・自社同系統重複拒否・他商会同系統・地区枠・通常6棟／専用1棟／系統3棟・解放と費用・個別稼働と上位化・監査／独占／精算・4種NPCの合法建設・旧保存ルール・外部スイッチ拒否。

PC/mobile E2E：テスト専用viewハーネスから実UIと実サーバーreducerを使用し、市場の店舗＋工房、個別マップ選択、個別上位化、個別稼働、幅超過なしを確認。製品側に検証用ルート・設定・変更APIを追加しない。従来の4人オンライン対局・再接続・再戦と他ゲームは総合verifyの既存E2Eで回帰確認する。
