# 表裏一体迷宮 Web実装 v1.0

ゲームIDは `two-sided-labyrinth`、アプリ版は `0.12.0`、ルール／保存互換性の版は `1.0-web.1`。

## 正式に採用した補完仕様

ユーザーの「提案を全て採用します」により、以下を正式仕様とする。

| 項目 | 仕様 |
| --- | --- |
| モード | オンライン2人協力／ローカル1人練習。共通の20面とCoreを使用 |
| 担当面 | オンラインはサーバーで席を固定。最初の参加者が表、次が裏 |
| 計時 | 両者の準備完了で開始。両面のゴール到達履歴が揃えば停止。切断中も継続 |
| 正式記録 | オンラインのチャレンジのみ。ステージ・ペア・ルール版で区別 |
| 1人練習 | 一時停止、ブラウザ内自動保存、再開。非選択側は自動操作しない。正式記録に混在させない |
| ステージ | チュートリアル10面＋チャレンジ10面を初めから自由選択 |
| 結果後 | 同じ面へ再挑戦、または同じ部屋でステージ選択へ戻る |
| 転送装置 | 本体マスは進入不可。隣接位置から操作 |

準備資料のCoreでは `transfer-port` が通行可能だったが、原稿の進入不可仕様を正式採用した。修正後も全20面の参照手順がクリアへ到達する。盤面・装置配置・初期アイテムは変更しない。

ペアは同じ部屋の匿名参加者ID2件をソートしたキー。同室再戦では同じキー、新しい部屋では別のキーになる。アカウント連携や公開ランキングは今回の範囲に含まれない。

## 出典とコード配置

出典はユーザー提供の「表裏一体迷宮_実装準備・全20面Core照合一式_v1.0.zip」と「表裏一体迷宮_実装準備・チャレンジCore接続_v1.0.md」。同梱v0.5の1人用モード仕様を含む。

- `src/games/two-sided-labyrinth/core/`：提供Coreと型定義。転送装置の通行修正、厳密な型チェックの補正、表示用読み取り関数を追加。
- `stages.json`：原稿由来の20面を一括収録。元のメタデータも保持。`readyForWebRuntime:false` は準備資料の由来を表し、Web実装の許可判定は `catalog.ts` の明示的な20面リストとCore検査で行う。
- `runtime.ts` / `module.ts`：準備・同時操作・タイマー・終了・GameRegistry接続。
- `view.ts`：本人の盤面、現在地、操作候補、アイテム、光路、電力、公開ゴール履歴のみを投影。
- `solo.ts`：受理済み操作列を同じCoreで再実行して保存を復元。任意の盤面状態を保存データから信用しない。
- `src/client/games/two-sided-labyrinth/`：ステージ選択、SVG盤面、移動・装置操作、ルール、結果、1人練習。

## 状態と操作

`PREPARING → PLAYING → FINISHED`。再戦では新しいmatchIdと初期状態で `PREPARING` へ戻る。ステージ選択へ戻る場合は同じセッション・参加者を維持して待機部屋へ戻り、ゲストの準備状態を解除する。

ゴール履歴は到達後に戻っても維持する。人がいるマスへ壁・穴を作る、使用中の影橋を消すなどの操作はCoreが拒否する。時間制限・操作回数上限は設けない。

両者の操作はDurable Object側で順に処理する。ゲーム中は各移動でphaseVersionを変えず、ほぼ同時に届いた相方の合法入力を古いフェーズ扱いにしない。ライフサイクル変更時は従来どおりバージョンを更新する。保存・配信・再接続処理も同じ直列化対象とし、休止復帰後は永続状態からViewを作る。

同じrequestIdは試合内で再処理しない。次試合開始時に履歴を切り替える。クライアントのplayerId／face申告は採用せず、認証済みWebSocketセッションからCoreの行為者を決める。

## UIと途中保存

- PCの1人練習は左右2面。モバイルも左右の全体図を残し、選択面の詳細を表示。ズーム・スクロール状態は各面で保持。
- オンラインは担当面のみ。盤面内のスクロール、拡大縮小、「現在地」への追従を備える。
- 矢印／WASD、タッチ移動、長押し移動。通信待ちや切断中は入力を止める。
- 装置の操作位置に来ると利用可能な操作が表示される。人の足元を変える危険な操作は無効理由を表示。
- 光路と鏡の向き、通行可否、配電盤ON/OFF、所持品・未受取品、共有電力を表示。
- 1人練習は毎操作と1秒ごとにlocalStorageへ保存。タブを離れると一時停止。保存を再開すると一時停止状態から始める。保存不可／非互換データは画面に明示する。
- 保存は同じブラウザ内の1枠。新しい練習開始時は既存保存の上書きを確認する。

## D1

`0008_two_sided_labyrinth.sql` は追加テーブル `labyrinth_records` と検索用indexを作る。既存ゲームのスキーマは変更しない。

正式記録はmatchIdを主キーとして冪等保存し、app_version・rules_version・stage_id・ONLINE_DUO・匿名pair_key・開始／終了時刻・経過ミリ秒・受理操作数を記録する。氏名・セッショントークン・相方盤面・生の操作内容は記録しない。共通 `playtest_matches` には参考タイムのオンライン試合も区別して残す。

D1は既存基盤の非同期ログ経路を利用する。D1障害時は運用エラー記録の対象となり、プレイ自体を止めない。保存完了保証のある再送キューは今回未実装。結果画面の「正式記録」はモード区分であり、D1書き込み完了通知ではない。

本番利用前には明示依頼のもとでmigration適用とdeployが必要。今回の作業では本番に適用しない。

## 検証範囲

標準ゲートは `npm.cmd run verify`。Windowsの正確な対象commit、終了コード、GitHub Actions結果はPRに記録する。

- 原稿20面のSHA-256照合。モード間で盤面を改変していないことを保護。
- tutorial 01〜10：455操作。challenge 01〜10：1,798操作。各操作を共通Coreで1人用／オンライン用双方に適用し一致を照合。
- 装置操作の参照手順は、画面の有効な操作候補にも含まれることを確認。
- チャレンジ3・4・7・10は位置だけでなく指定されたアイテム・電源・扉などの参照状態を照合。
- 高出力光源の給電中取り外し拒否、使用中の影橋消失拒否、転送装置への進入拒否。
- 認証済み担当面、個別View、同時移動、requestId再送、休止復帰、古いphaseVersion、終了前のステージ変更拒否。
- SQLite全migration適用、正式記録の冪等保存と参考タイムの除外。
- PC／mobile Chromium E2E：ソロの左右表示・切替・拡大・保存・再開・クリア、オンライン2人の開始・操作・reload・offline／スリープ復帰・チャレンジクリア・ローカルD1正式記録・ステージ変更・再戦。
- 既存『ポンはいない』『商都開発』『大石のテリトリー』の共通テストも実行。

参照手順の再生は全状態網羅探索や最短性の証明ではない。新Coreによるチャレンジ全状態探索、人間2人でのプレイ感評価、本番のスマートフォン実機通信試験は完了扱いにしない。
